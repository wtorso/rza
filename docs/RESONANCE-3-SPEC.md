# RESONANCE-3 — спецификация минимальной модели владения

Статус: проект спецификации v0.3. Не скомпилировано, не верифицировано.
Честная оценка новизны: 7/10 до артефактов (чекер, листинги стирания,
метрика ИИ+чекер); 8–9/10 только после публикации артефактов.

## 0. Происхождение и prior art (цитируется до вопросов, не после)

- Плекс: Douglas Ross, APT, 1956 — блоки памяти, слова-указатели, заголовки.
- Поколения в ссылках: capability-машины 1970-х; slotmap/generational arena; ECS entity handles.
- Дерево времён жизни: region-based memory (Tofte–Talpin, ML Kit), lexical scope, RAII.
- Ближайший родственник: WebAssembly Component Model (own/borrow resource handles) —
  там владение динамическое (таблицы); у нас — статическое (дерево + поколения).
- Предостережение: UNCOL (1958) — судьба «универсальных IR». Защита: операция
  добавляется только если без неё невыразим класс ОШИБОК, а не класс программ.

## 1. Кирпичи (четыре) и имена

| Имя       | Кирпич  | Тип                    |
|-----------|---------|------------------------|
| Field     | пул     | Pool — типизированная память системы |
| Cavity    | рамка   | (Name, Body) — ПАРА типов: Name бессмертно (gen: Nat), Body смертно (арена) |
| Resonator | ячейка  | Cell@F — память, параметризованная рамкой-владельцем |
| Mediator  | связь   | Link(C, g) — адрес + поколение; единственный способ адресации ячейки, своей или чужой (AUDIT-1/#4) |
| Cascade   | шаг     | Step([Link] → Cell) — единственная операция |
| Decay     | переход | leave: Frame → ⊥ — единственный деструктор в системе |

Принцип «две жизни полости» (RESONANCE-2) поднят в типы: смешение Name и Body
— ошибка компиляции, а не аккуратность программиста. ABA закрыта грамматикой.

## 2. Операции (восемь, исчерпывающе)

  enter(parent) -> Frame        — рождение рамки
  leave(f)                      — Decay: gen++, арена мертва, один переход
  resonator(f, size) -> Cell@f  — опора в рамке
  mediator(c) -> Link           — выдача прохода (владельцем ячейки или предком)
  read(l) -> Cell | DEAD        — единственное чтение чужого
  cascade([l...], out: Cell)    — шаг; DEAD на входе = атомарный abort;
                                  out — всегда НОВАЯ ячейка (AUDIT-1/#6)
  raise(c, f')                  — подъём опоры: f' — строгий предок (I4)
  alive?(l) -> bool             — операция наблюдения: всегда сообщает статус
                                  (AUDIT-2/п.5; «no-op+лог» — семантика
                                  намерения кода на мёртвой связи, не probe)

## 3. Инварианты (чекер, O(n))

  I1  resonator@F:    F — текущая рамка или предок
  I2  mediator(c):    выдаёт владелец c или предок владельца
  I3  cascade:        sync — все Link живы на входе (проверка один раз на границе);
                      async — все Link указывают в ячейки корневой рамки (Field),
                      и обязан быть названный потребитель (out-Link)
  I4  raise:          только вверх по дереву

Ключевое свойство: частичный порядок времён жизни ограничен ДЕРЕВОМ.
«Переживёт ли X шаг Y» — сравнение глубин, O(1). Вся проверка программы —
один обход. Порождение легальных программ — конечным автоматом.
Это сознательное урезание выразительности ради проверяемости — главная
заявка на новизну. Циклы и совладение — вне модели: отступление по протоколу
(одна рамка Frame(GC) с внутренним GC, наружу — только Link).

## 4. Стирание (что платит машина)

  resonator  → bump-аллокация / alloca     — 1 инструкция
  read       → cmp gen + branch            — 2 инструкции, только на границах
  cascade    → call                        — 0 накладных
  leave      → сдвиг указателя арены       — 1 инструкция (стековая арена: 0)
  mediator   → {ptr, frame*, i32}          — две проверки на границе
               (указатель владельца + поколение); стирается в sync-каскадах
               (AUDIT-1/#4: претензия на «0 накладных» снята — медиатор
               адресует ячейку, а не только рамку, 16–24 байта)

Рантайма нет. Дисциплина стирается; остаются проверки поколений на границах —
видимые в листинге поштучно. Async-каскад платит ровно за свои границы.

## 5. Три потребителя — один объект

- Человек: рисует дерево рамок + карту связей. Это и есть типовая сигнатура
  системы; дифы архитектуры = дифы дерева, а не дифы кода.
- ИИ: генерирует кирпичи; чекер в петле отвергает нелегальное за миллисекунды
  с указанием операции и правила. Классы ошибок LLM (висячая ссылка,
  двойное освобождение, неверное время жизни) — невыразимы или ловятся I1–I4.
- Компилятор: маппинг в LLVM прямой (раздел 4); горячий sync-путь — ноль
  лишних инструкций против чистого C.

## 6. Границы (признаются, а не заметаются)

1. Вычислительные ядра (матрицы, кодеки): одна большая рамка + сырые указатели
   внутри; модель не лезет.
2. Циклические графы / shared ownership: Frame(GC), протокол отступления.
3. Распределённые системы: Link не переживает сеть; аналог — lease/fencing
   tokens, но это другой механизм, цитируем, не натягиваем.
4. «Девятая операция» — главный риск смерти (см. UNCOL).

## 7. Дорожная карта артефактов (каждый — ворота для следующего)

  A. Чекер I1–I4: цель < 500 строк. Расползается — кирпичей не четыре. СТОП.
  B. Транслятор кирпичей → C3 (скелет resonance2-c3 уже реализует семантику).
  C. Листинги стирания: sync-каскад против эквивалентного C, diff = 0 на горячем пути.
  D. Метрика ИИ: доля программ без ошибок владения «с чекером в петле» vs без.
     Без D — оценка новизны остаётся 7/10 навсегда.
