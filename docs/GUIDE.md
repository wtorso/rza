# REZ3-ASM (.rza) — руководство по языку

Учебник и справочник для человека без опыта в ассемблере: от первой
программы до производительного кода. Норматив — SPEC.md (этот документ
его не заменяет, а учит); границы и открытые вопросы — SPEC §8–§9;
цена инструкций — SPEC §4 и docs/PERF.md; стирание — docs/ERASURE.md.

---

## 1. Что это за язык

`.rza` — минимальный ассемблер, в котором **памятью владеют явно**.
Обычный ассемблер даёт вам регистры и всю память сразу; `.rza` даёт
регистры и память, нарезанную на **ячейки**, до которых можно дотянуться
только через **медиаторы** (проходы), умирающие вместе со своей
рамкой-владельцем. За это чекер гарантирует: ни висячих указателей,
ни use-after-free, ни двойного освобождения — всё это синтаксически
невыразимо, а не «ловится в отладчике».

Компиляция: `.rza` → проверка инвариантов (один проход, O(n)) →
C99 → ваш C-компилятор. Ошибка владения = программа не компилируется
(а не падает у пользователя).

Четыре кирпича модели (больше ничего нет):

```
field (бессмертный корень)
  └── cavity  (рамка: имя-поколение + арена памяти)
        ├── resonator  (ячейка: байты в арене рамки)
        └── mediator   (проход к ячейке: {ячейка, владелец, поколение})
decay — единственный деструктор: гасит рамку и всё поддерево атомарно
```

## 2. Инструментарий за 2 минуты

```sh
cd rez3-asm
./rez3asm.exe prog.rza                 # только проверка (петля «написал →
                                       #   проверил» — основная)
./rez3asm.exe prog.rza --emit-c -o prog.c   # C99 с main
zig cc -O2 -I refs -I . prog.c -o prog      # сборка (см. bond/run.sh)
./prog                                  # запуск
```

Режим `--emit-lib` — C99-библиотека без main для встраивания в хост
(так ядра bond живут внутри игры на C3): верхний уровень → `rza_boot`,
`proc name:` → `rza_name`, геттеры `rza_frame_NAME` / `rza_med_NAME`
(SPEC §11). VS Code: расширение `rez3.rza` — подсветка и диагностика
чекера в редакторе.

## 3. Машина

### Регистры

Шестнадцать регистров `%r0`..%r15`, каждый — знаковый 64-битный (i64).
Никаких специальных ролей язык не назначает: ни аккумулятора, ни
указателя стека, ни регистра флагов — **флагов нет вовсе** (AUDIT-2/п.6).
Регистры локальны для текущего контекста: при `call` процедура получает
свежие обнулённые `%r0..%r15` (SPEC §6) — обмен данными между процедурами
только через ячейки.

### Память

Вся память — в ячейках. Сырого адреса не существует как значения: нет
инструкции «адрес в регистр», нет арифметики над адресами. Читать и
писать можно только так:

```
load  %r0, [acc_m + 0]     ; i64 из ячейки через медиатор acc_m
store [acc_m + 8], %r0     ; i64 обратно
loadb %r1, [tab_m + %r2]   ; БАЙТ (zero-extend) — таблицы байтов
```

Смещение — константа или регистр (индексная адресация, AUDIT-4).
Записи байта нет: байтовые таблицы пишутся словами i64 (ячейки
выровнены по 16). Память свежей ячейки — **нули** (AUDIT-6): чтение
незаписанного даёт 0, детерминированно.

### Программа

Плоский текст: одна инструкция на строку, комментарий — `;` до конца
строки, метка — `name:` на своей строке. Числа — десятичные или
`0x…`, с минусом; константа в `mov` — до 32 бит (AUDIT-4). Верхнеуровневый
код исполняется сверху вниз; завершается `ret` (последняя инструкция).

## 4. Первая программа

```
; hello.rza — счётчик в field-ячейке (field бессмертен, объявлять
; его не нужно)
res  acc, field, 8          ; ячейка 8 байт (один i64) в корневой рамке
med  acc_m, acc, field      ; проход к ней выдаёт field (владелец)

mov  %r0, 0
store [acc_m + 0], %r0      ; acc = 0
mov  %r0, 41
load %r1, [acc_m + 0]
add  %r2, %r0, %r1          ; 41 + 0
store [acc_m + 0], %r2      ; acc = 41
print %r2                   ; 41
ret
```

Вывод: `41`. Проверено `rez3asm` (как и все примеры ниже).

Три обязательных шага видны сразу: **создать ячейку** (`res`),
**получить проход** (`med`), **работать только через проход**
(`load`/`store`). Имя медиатора — с суффиксом `_m`, все имена — в нижнем
регистре (`[a-z_][a-z0-9_]*`) — дисциплина имен машинная, не стилевая.

## 5. Владение по шагам (сердце языка)

### 5.1 Рамки — дерево жизней

```
cav  session, field        ; рамка session, ребёнок field
cav  level, session        ; рамка level, ребёнок session
res  grid, level, 192      ; ячейка в арене level (192 байта, нули)
med  grid_m, grid, level   ; проход выдаёт владелец (level)
```

- `cav NAME, PARENT` — новая рамка, ребёнок ЖИВОЙ рамки (или `field`)
  [I1]. Дерево строгое: циклов владения нет.
- `decay level` — рамка, её поддерево и все ячейки мертвы **атомарно**,
  одним событием. `decay field` запрещён; двойной `decay` — ошибка.
- После `decay` медиаторы на ячейки рамки — мёртвые проходы: `load` по
  ним — `FAULT … dead mediator` в stderr и `exit(1)` в runtime (не UB!).

Типовой жизненный цикл (как в игре): партия → экран → кадр — каждый
слой рамка; выход с экрана = `decay screen` = все акторы умерли разом,
без подчистки по одному.

### 5.2 Медиаторы — кто выдаёт

`med NAME, RES, ISSUER`: выдающая рамка — владелец ячейки или её предок
[I2]. Выдать проход к чужой ячейке можно только «сверху» по дереву.
Это и есть весь контроль доступа.

`probe MED` — наблюдение: печатает ровно `ALIVE` или `DEAD`. Для отладки
и тестов (тест `dead_link.rza`).

### 5.3 raise — переприбивка ячейки к предку

`raise RES, CAV` — ячейка меняет владельца на строгого предка [I4];
старые медиаторы мертвы (выдайте новые). Статическая операция: память
физически остаётся в арене рождения (SPEC §9) — не читайте поднятую
ячейку после decay рамки рождения.

## 6. Система команд — полная таблица

Стоимость — из таблицы стирания SPEC §4 (машинных инструкций при -O2,
типично). «проверка» = распечатка медиатора (владелец жив + поколение).

### Владение

| Инструкция | Семантика | Цена |
|---|---|---|
| `cav name, parent` | новая рамка — ребёнок живой рамки | malloc ×2 |
| `res name, frame, size` | ячейка size байт (нули), переполнение арены → FAULT | bump ×3 |
| `med name, res, issuer` | проход к ячейке от владельца/предка | 3 store |
| `raise res, frame` | перевладение к строгому предку (статически) | 0 |
| `decay frame` | рамка + поддерево мертвы атомарно | gen++ + free |
| `probe med` | печать `ALIVE`/`DEAD` | printf |

### Данные

| Инструкция | Семантика | Цена |
|---|---|---|
| `mov %rD, imm` / `mov %rD, %rS` | константа (i32) или копия | 1–2 |
| `load %rD, [MED+off]` | чтение i64 (+проверка вне каскада) | ~6–8 |
| `loadb %rD, [MED+off]` | чтение байта, zero-extend | ~6–8 |
| `store [MED+off], %rS` | запись i64 (+проверка вне каскада) | ~6–8 |
| `add sub mul div mod and or xor shl shr %rD, %rA, %rB` | D = A ∘ B; B может быть константой (AUDIT-5) | 1–2 |
| `inc %rN` / `dec %rN` | ±1 | 1 |
| `print %rN` | печать i64 десятично | printf (медленно!) |

**Порядок операндов критичен для некоммутативных операций**:
`sub %rD, %rA, %rB` считает `D = A − B`. Пишете «K − x»? —
`mov %r8, K` затем `sub %r8, %r8, %rX` (а не `sub %r8, %rX, %r8` —
это `x − K`, знак инвертирован; прецедент — bond en_step, см. §10).
Для проверок равенства (только `brz`/`brnz`, без знака) порядок
безразличен: `a − b == 0` симметрично.

`div`/`mod` на нуле — поведение C (UB; SPEC §9). Не делите на ноль.

### Поток

| Инструкция | Семантика |
|---|---|
| `name:` | метка текущего блока |
| `jmp name` | безусловный переход |
| `brz %rN, name` | переход, если регистр == 0 |
| `brnz %rN, name` | переход, если регистр != 0 |
| `proc name:` … `ret` | процедура (одна точка ret) |
| `call name` | вызов (свежие регистры внутри) |
| `ret` | выход из proc / конец программы на верхнем уровне |

Переходы — только внутри своего лексического блока (верхний уровень,
тело proc, тело каскада). `jmp` между блоками — violation [STRUCT].
Нелокальный выход — это `decay` рамки.

## 7. Сравнения без cmp: идиомы

Флагов нет: ветвимся по регистру. Приём для знака: `shr %rT, %rX, 63` —
в %rT попадает знаковый бит (1 = отрицательно). Библиотека идиом
(проверены; везде `t` — скретч):

```
; a == b            ; a != b
sub  %rT, %rA, %rB  sub  %rT, %rA, %rB
brz  %rT, yes       brnz %rT, yes

; a < b             ; a >= b
sub  %rT, %rA, %rB  sub  %rT, %rA, %rB
shr  %rT, %rT, 63   shr  %rT, %rT, 63
brnz %rT, yes       brz  %rT, yes

; a <= b            ; a > b
sub  %rT, %rB, %rA  sub  %rT, %rB, %rA     ; b - a < 0  ⟺  a > b
shr  %rT, %rT, 63   shr  %rT, %rT, 63
brz  %rT, yes       brnz %rT, yes
                          ; внимание: обе формы через b−a

; |x| < K (K > 0): два теста — «x > -K» и «x < K»
mov  %rT, K
add  %rT, %rX, %rT       ; x + K
brz  %rT, no             ; x == -K — строгость сам выбираешь
shr  %rT, %rT, 63
brnz %rT, no             ; x < -K
mov  %rT, K
sub  %rT, %rT, %rX       ; K - x (порядок: сначала K в приёмник!)
brz  %rT, no             ; x == K
shr  %rT, %rT, 63
brnz %rT, no             ; x > K
; дальше — |x| < K
```

Строгость границ (`<` vs `<=`) решается отдельным `brz` до знакового
теста — пишите границу комментарием (норма AUDIT-3: граница с выводом).

## 8. Таблицы и индексная адресация

```
res  tab, session, 1600
med  tab_m, tab, session
; ...
mov  %r2, 5                 ; индекс
mul  %r2, %r2, 8            ; ×8 байт на i64-элемент (адресация — БАЙТЫ)
load %r0, [tab_m + %r2]     ; tab[5]
```

Байтовые таблицы (справочники, паттерны) — через `loadb`; знаковые байты
храните со сдвигом (bias): байт = значение + BIAS, после `loadb`
вычитаете BIAS (прецедент: wobtab босса в bond, bias +2).

## 9. Процедуры

```
res  counter, field, 8        ; счётчик бессмертен — в field
med  counter_m, counter, field

proc tick:
    load  %r0, [counter_m + 0]
    inc   %r0
    store [counter_m + 0], %r0  ; tick: counter += 1
    ret

call tick
call tick
load %r0, [counter_m + 0]
print %r0                  ; 2: два вызова tick по field-ячейке
ret
```

Правила (SPEC §6):

- Регистры приватны вызову: `call` даёт чистые `%r0..%r15`, `ret` их
  гасит. Параметров нет — обмен только через ячейки и медиаторы.
- Один `ret` на proc: ранний выход — `jmp` на финальную метку.
- Вложенные proc запрещены; рекурсия запрещена (прямая — статически,
  косвенные циклы — правилом проекта: их нет).
- Внутри proc видны: локальные имена, `field`, глобальные рамки и ячейки,
  глобальные медиаторы на ячейки `field` и глобальных рамок (AUDIT-4).
  Чужие proc-медиаторы и ячейки proc-рамок — [SCOPE].
- Рамки/ячейки, созданные внутри proc, глобальны (общая хроника
  лайфсайкла, AUDIT-3) — так пишется lib-режим (ядра bond).

## 10. Каскады: атомарные батчи со стиранием

```
casc settle: hp_m, pos_m -> out[session]
    load  %r0, [hp_m + 0]
    load  %r1, [pos_m + 0]
    add   %r2, %r0, %r1
    store [hp_m + 8], %r2
endc
```

- На входе все медиаторы из списка проверяются ОДИН раз [I3]; тело —
  голая адресная арифметика без проверок (стирание: docs/ERASURE.md).
- Первый мёртвый медиатор в runtime = атомарный abort: блок пропускается
  ЦЕЛИКОМ (не наполовину), программа продолжается. «Abort» ≠ «fault»:
  exit-код не меняется — это про отмену батча, не про аварию.
- В теле — только data-инструкции и только медиаторы из списка входа;
  `jmp` наружу — violation; выход — `endc` или abort.
- `out[CAV]` — всегда новая ячейка в рамке CAV (8 байт, SPEC §9).

**Когда каскад уместен**: батч, который обязан быть целиком (снимок
итогов, пересчёт связанных полей). **Когда нет**: перфреймовый цикл —
«abort» не значит «пропустить кадр» (прецедент P8: enemies-цикл bond —
proc, не casc).

## 11. Производительность: как писать быстрый .rza

Замеры на боевом ядре bond (900 кадров, docs/PERF.md): при -O2 ядро на
.rza идёт **с той же скоростью**, что рукописное C3; без оптимизации —
×2–3 медленнее. Выводы для практики:

1. **Всегда собирайте с -O2.** Проверки медиаторов инлайнятся и
   предсказываются; регистры %rN садятся в аппаратные.
2. **Горячие пути — через каскады или proc**: проверка медиатора на
   входе каскада — один раз на батч, дальше сырой доступ (1 инструкция
   на обращение против ~6–8 вне каскада).
3. **`print` — это printf**: не в циклах. Для отладки — точечно,
   перед коммитом убрать (прецедент: спам `32 -1` из забытого print).
4. **Таблицы — loadb по вычисляемому смещению** вместо цепочек
   сравнений; физика bond (парабола прыжка) — так и сделана.
5. **Структура рамок = структура времени жизни данных**: не плодите
   decay в горячем цикле; рамка «на экран/партию» дешевле тысячи
   мелких ячеек.
6. Помните про отсутствие bounds-checks (SPEC §9, P4): смещение за
   пределы ячейки пишет в соседнюю память арены — модель ловит время,
   не пространство. Дисциплина: размеры ячеек и смещения — константами
   с комментарием-выводом (как карта смещений в шапке bond.rza).

## 12. Диагностика: читаем ошибки

Статика (программа не компилируется, exit 1, ВСЕ нарушения списком):

```
VIOLATION line 42 [I3]: sync cascade aborted: dead link on entry settle hp_m
VIOLATION line 57 [STRUCT]: load via unknown mediator pos_m
```

| Правило | Причина | Лечение |
|---|---|---|
| I1 | ячейка/рамка в мёртвой рамке | decay раньше создания — переупорядочить |
| I2 | issuer медиатора — не владелец и не предок | выдавать из рамки-владельца/предка |
| I3 | вход каскада: медиатор мёртв/неизвестен | каскад текстуально до decay (прецедент: snap_stats до mission_end) |
| I4 | raise не к строгому предку | выбрать предка по дереву |
| DECAY | decay field / дважды / рамки proc | убрать; рамку proc гасит ret |
| DUP | имя занято в скоупе | переименовать |
| STRUCT | неизвестная инструкция/метка, переход между блоками, владельческая операция в каскаде, код после верхнего ret | см. текст сообщения |
| SCOPE | из proc виден не тот медиатор | медиатор на field/глобальную ячейку, либо геттер в lib-режиме |

Runtime: `FAULT line N: dead mediator M` + exit 1 (обращение по мёртвому
проходу вне каскада); `ABORT line N: cascade …` (батч отменён — ищите,
кто убил рамку раньше времени); `FAULT … arena overflow` — ячейка не
влезла в арену рамки: увеличьте SIZE-ы (ёмкость рамки = сумма res +
выравнивание, SPEC §4).

## 13. Границы (чего язык не делает — осознанно)

Нет: циклов владения, векторизации/SIMD, самомодифицирующегося кода,
адресной арифметики вне медиаторов, async-транспорта (acasc синхронен),
bounds-checks, сборки мусора, рекурсии, констант сверх i32 в `mov`.
Полный список с причинами — SPEC §8–§9. Если упёрлись — это не баг,
а граница модели; обход — через архитектуру данных, не через хак.

## 14. Шпаргалка (одна страница)

```
res  x, frame, SIZE     med  x_m, x, issuer     ; ячейка + проход (_m!)
cav  f, parent          decay f                 ; рамка: рождение/смерть
load %r0, [x_m + 0]     store [x_m + 8], %r0    ; i64
loadb %r1, [x_m + %r2]                          ; байт
mov  %r0, 42   inc %r0   dec %r0   print %r0
add/sub/mul/div/mod/and/or/xor/shl/shr %rD, %rA, %rB   ; D = A ∘ B
lbl:  jmp lbl   brz %r0, lbl   brnz %r0, lbl
proc p: … ret   call p
casc c: a_m, b_m -> out[field] … endc           ; атомарный батч
acasc c: g_m -> gout … endc                     ; только field-ячейки
probe x_m                                       ; ALIVE/DEAD
; сравнение: sub %rT, %rA, %rB → brz/brnz (==/!=) или shr %rT,%rT,63 (знак)
; ПОМНИ: sub %rD, %rA, %rB = A−B — «K−x» пишется sub %rD, %rD, %rX
```

модели в цифрах; bond/arch/bond.rza — большая боевая программа
