# .rza: цена модели — замеры и границы (perf-анализ)

Замер: `bond.exe --smoke`, 900 кадров полной партии (phys_step + en_step +
мир), wall time по `std::time`. Машина: Windows, x86_64. Таймер шумный
(встречаются нулевые отсчёты — артефакт квантования, отброшены).

## Числа (900 кадров)

| сборка | C3-ядро (эталон) | .rza-ядро | отношение |
|---|---|---|---|
| оба без оптимизации (zig cc -O0 / c3c -O0) | ~1.0 мс | ~2.0–3.2 мс | **×2–3** |
| оба с -O2 | ~1.0 мс | ~0.7–1.1 мс | **≈ ×1 (паритет)** |

Вывод: оверхед модели RESONANCE-3 — это оверхед **неоптимизированного**
кода, а не семантики. После -O2 проверки поколений инлайнятся и
предсказываются, «регистры» %r0..%r15 (локальные int64_t в эмитированном
C) садятся в настоящие регистры, и ядро на .rza идёт с той же скоростью,
что рукописное C3. Для сравнения с fasm: ручной fasm для такой нагрузки
(ветвистая логика поверх ячеек памяти, а не векторные вычисления) дал бы
тот же класс чисел, что C3 -O2 — то есть **.rza при -O2 стоит на уровне
ручного ассемблера** по скорости, оставляя проверки владения.

## Откуда оверхед при -O0 (и куда он девается при -O2)

1. `rez_deref_cell` на каждый `load`/`store` вне каскада: вызов + проверка
   {owner, alive, gen}. При -O2: статическая функция инлайнится, проверка
   — два предсказанных бранча. В каскаде (casc) проверка одна на входе —
   стирание (docs/ERASURE.md).
2. Регистры как переменные: при -O0 каждый %rN — слот в стеке; при -O2 —
   аппаратные регистры.
3. `proc` = C-функция + `rez_frame_reset` (освобождение/перевыделение
   арены на вызов): на горячем пути не используется (phys_step/en_step
   вызываются раз в кадр, не на сущность).

## Границы языка, влияющие на скорость (осознанные)

- **Нет bounds-checks** (SPEC §9, P4): медиатор не несёт размера — цена
  временной безопасности нулевая по данным; пространственная — на
  программисте (как в asm). Добавление bounds = +1 сравнение на обращение
  (оценка +10–20% на -O2 по аналогии с gen-проверкой) — отдельное решение.
- **Арены bump**: ячейка = смещение в арене, нет per-cell heap — calloc/
  free один раз на рамку (decay — O(1)).
- **Нет GC/подсчёта ссылок**: поколение — 32-битное сравнение.
- **div/mod** — аппаратные (процентные таймеры в en_step — `mod`).

## Дорожная карта оптимизаций (если понадобится)

1. **Хоистинг deref в proc**: внутри proc без `decay`/`call` в рамку-
   владельца медиатор не может умереть — статически доказуемо; можно
   эмитить один deref на proc вместо одного на обращение. Ожидаемый
   эффект при -O2 мал (бранчи предсказаны), при -O0 — убирает основной
   оверхед.
2. **Расширение casc-стиля**: батчи обращений к одной ячейке через вход
   каскада (как snap_stats) — семантика + скорость одновременно.
3. **-O2 по умолчанию** — сделано (run.sh: zig cc -O2, c3c -O2).

Не делать: SIMD/векторизация и вычислительные ядра — вне границ языка
(SPEC §8); самомодифицирующийся код — вне модели.
