# Норма тестирования (AUDIT-3, нормативно)

Каждое ожидаемое значение пишется **с выводом**, а не как магическая константа.
Комментарий у `print`/`probe` обязан объяснять, почему ожидается именно это:

```
print %r4   ; 55: после 10 итераций (a,b)=(F(10),F(11))=(55,89); печатаем a
print %r5   ; 42 = 20 + 22 (a + b, sync-каскад addup)
```

Эталон, который нельзя перепроверить без исполнения, — бомба замедленного
действия: «печатает число Фибоначчи» легко принять за «печатает правильное»
(55 и 89 — соседние). Прецеденты: трёхоперандный эталон против двухоперандной
грамматики; `store %r1` (89) вместо `store %r0` (55) в fib. Обе ошибки пойманы
прогоном, а не ревью — человеческое ревью такое пропускает.

## Как добавить тест в rez3-asm

Тест регистрируется строкой в `run_tests.sh` (`run_good/run_viol/run_dead/
run_lib NAME`). Механика:

1. Легальный (`run_good`): `tests/NAME.rza` + `tests/NAME.expected`
   (точный stdout, LF) — транслируется, компилируется с нулём warnings,
   stdout сверяется с .expected.
2. Примеры GUIDE.md — та же механика `run_good` с `DIR=docs/examples`
   (`docs/examples/*.rza` + `.expected`): регрессия учебника, примеры
   обязаны проходить.
3. Негативный (`run_viol`, viol_*): файл должен отвергаться с exit 1 и
   именем правила в stderr; .expected не нужен.
4. Runtime-fault (`run_dead`, как dead_link/ret_dead): транслируется, при
   запуске exit≠0, stderr содержит `FAULT`.
5. Lib-режим (`run_lib`): `tests/lib_NAME.rza` --emit-lib + линковка с
   `tests/lib_NAME.harness.c` (если нет — общий `tests/lib_harness.c`),
   запуск, сверка с .expected; `run_lib_compile` — только трансляция и
   компиляция, без запуска.
6. Каждая ветка чекера обязана иметь тест. Новое правило = новый
   viol_-тест.
7. Прогон: `cd rez3-asm && bash run_tests.sh` → 75/75 PASS, exit 0
   (пересобирает rez3asm.exe, компилирует легальные с -std=c99 -pedantic
   -Wall -Wextra ноль warnings, сверяет stdout, отвергает незаконные).

Подробности: `rez3-asm/SPEC.md` §10.
