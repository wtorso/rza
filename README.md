# REZ3-ASM (.rza) — ассемблер владения

Типизированный ассемблер поверх модели RESONANCE-3: владение выражено в
тексте программы и проверяется за один текстовый проход. Транспайлер
`rez3asm.c3` (C3 0.8.5) → C99. Норматив: `SPEC.md`. Этот файл — краткое и
ясное введение. **Учебник с нуля: `docs/GUIDE.md`** (машина, регистры,
вся система команд, идиомы сравнений, каскады, производительность,
справочник ошибок; примеры — `docs/examples/*.rza`, вывод проверен
прогоном).

## Ментальная модель за минуту

Программа — это **летопись дерева владения**. Не поток управления, а
хроника: что родилось, кому выдано полномочие, что умерло.

- **Рамка** (`field`, `cav`) — владелец. `field` бессмертен и существует
  неявно; остальные рамки образуют дерево и умирают ровно один раз
  (`decay`) — вместе со всем поддеревом, одним событием.
- **Ячейка** (`res`) — память в арене рамки. Умирает с рамкой.
- **Медиатор** (`med`) — проход к ячейке: указатель, текущий и домашний
  владельцы, поколения и размер. Сырого адреса в языке нет. Мёртвая рамка
  меняет поколение, а обращение по мёртвой связи или вне ячейки даёт `FAULT`.
- **Каскад** (`casc`/`acasc`) — единственный шаг вычисления, пересекающий
  границы рамок.
- **Decay** (`decay`) — единственный деструктор системы.

Проверка программы — один текстовый проход; проверка предка зависит от
глубины дерева, а decay — от размера поддерева. Дерево вместо произвольного
графа — сознательное ограничение ради простой механической проверки.

## Каскад — сердце языка

Каскад — блок, который трогает чужие ячейки. Два ортогональных режима:

**sync** — `casc NAME: M1,M2 -> OUT[CAV]` … `endc`

```
cav  session, field
res  draft, session, 16
med  draft_m, draft, session
casc edit: draft_m -> view[session]
    load  %r0, [draft_m + 0]   ; проверка поколения — ОДИН раз на входе
    add   %r1, %r0, %r0
    store [draft_m + 8], %r1   ; внутри — сырые смещения, ноль проверок
endc
```

- Все медиаторы обязаны быть живы на входе [I3] — проверяется статически.
- В runtime первый мёртвый медиатор = **атомарный abort**: блок
  пропускается целиком, программа продолжается. Не исключение, не UB —
  пропуск шага.
- Проверка жизни делается один раз на входе; постоянные смещения проверяет
  компилятор. Для вычисляемых смещений остаётся проверка границ.
- OUT — всегда новая ячейка; запись в существующую — через `store`.
- Из тела нельзя выпрыгнуть: выход только через `endc` или abort.

**async** — `acasc NAME: M1 -> OUT` … `endc`

Эффект, переживающий рамку (фон, отложенная задача). Правило: все
медиаторы и OUT — только в `field`. Если потребителя назвать не можете —
эффект не должен быть async; это не ограничение чекера, это диагноз
дизайна. OUT в field и есть «названный потребитель» — инвариант
механический, проверяется.

## Правила I1–I4 как таблица «что будет, если…»

| Правило | Смысл | Типичная ошибка | Диагностика |
|---|---|---|---|
| I1 | `res` — только в живой рамке | ячейка после `decay` рамки | `VIOLATION [I1]: cell in dead frame` |
| I2 | `med` выдаёт владелец или предок | соседняя рамка выдала проход | `[I2]: link issued by non-owner` |
| I3 sync | вход каскада — все медиаторы живы | каскад по проходу после decay | `[I3]: dead link on entry` |
| I3 async | связи и OUT — только field | фон держит ссылку на смертное | `[I3]: non-root link` |
| I4 | `raise` — только к строгому предку | подъём вбок/вниз | `[I4]: raise to non-ancestor` |
| DECAY | одна рамка — одна смерть | двойной `decay`, `decay field` | `[DECAY]: double leave` |

## Стирание (что платит машина)

| Инструкция | В C99 | Цена |
|---|---|---|
| `res` | checked bump-аллокация + memset | ветки + обнуление |
| `load`/`store` вне каскада | проверка жизни и границ | на каждом обращении |
| `load`/`store` в каскаде | `memcpy` для постоянного смещения | проверки стерты |
| вычисляемое смещение | `rez_cell_bounds` | одна проверка доступа |
| `casc` | блок + goto abort | проверки один раз на входе |
| `decay` | инвалидация static арен + gen++ | O(размер поддерева) |
| `med` | указатели, поколения, size | цена видна на границе |

Внешнего runtime нет: статические helpers включаются в C99. Рамки и арены
выделяются как static storage, без `malloc/free`. Полная таблица — SPEC.md §4.

## Инструментарий

```sh
rez3asm file.rza              # проверка: VIOLATION line N [RULE] в stderr
rez3asm file.rza --emit-c     # C99 на stdout (читаемый, для людей)
rez3asm file.rza --emit-lib   # C99-библиотека: procs → void rza_NAME(void)
rez3asm file.rza -o out.c     # -o без флагов тоже включает эмиссию C
rez3asm --lsp                 # LSP-сервер на stdio (диагностика в редакторе)
bash run_tests.sh             # 97/97 + ноль warnings, UBSan и fuzz-smoke
```

- `rez3asm.c3` — транспайлер на C3 0.8.5;
  `lsp_server.c3` — LSP-сервер внутри той же программы (флаг `--lsp`,
  чекер зовётся из памяти, без временных файлов).
- `refs/rez3.h` (заморожен) + `refs/rez3ext.h` (расширение: `RezCellMed`,
  нуле-инициализация ячеек; правило AGENTS.md — rez3.h не менять,
  расширять только новыми сущностями в ext).
- `tests/` — легальные и `viol_*` программы; норма AUDIT-3: ожидаемые
  значения — с выводом, не магические константы.
- `editors/vscode/` — расширение `rez3.rza` (подсветка + LSP-клиент,
  запускает `rez3asm --lsp`).

## Пример целиком (tests/fib.rza)

```asm
cav  main, field
res  acc, main, 16
med  acc_m, acc, main

mov  %r0, 0
mov  %r1, 1
mov  %r2, 10

loop:
    brz  %r2, done
    add  %r3, %r0, %r1
    mov  %r0, %r1
    mov  %r1, %r3
    dec  %r2
    jmp  loop

done:
    store [acc_m + 0], %r0   ; 55: после 10 итераций (a,b)=(F(10),F(11))
    load  %r4, [acc_m + 0]
    print %r4
    decay main
    ret
```

## Воспроизводимый пример каскада

`tests/cascade.rza` показывает sync, async и raise. Актуальный листинг его
C99 разобран в `docs/ERASURE.md`: проверки жизни выполняются на входе,
постоянные смещения стираются, опасная арифметика получает явные guards.

## Границы

Циклические графы и совладение — вне модели. Async-транспорт отсутствует:
`acasc` синхронен. Поднятая ячейка физически живёт в домашней арене. Деление
на ноль, overflow деления и недопустимые сдвиги дают `FAULT`, а не UB.
Полный список — SPEC.md §8–§9.
