# REZ3-ASM (.rza) — ассемблер владения

Типизированный ассемблер поверх модели RESONANCE-3: владение выражено в
тексте программы и проверяется статически за один проход O(n). Транспайлер
`rez3asm.c3` (C3 0.8.4) → C99. Норматив: `SPEC.md`. Этот файл — краткое и
ясное введение.

## Ментальная модель за минуту

Программа — это **летопись дерева владения**. Не поток управления, а
хроника: что родилось, кому выдано полномочие, что умерло.

- **Рамка** (`field`, `cav`) — владелец. `field` бессмертен и существует
  неявно; остальные рамки образуют дерево и умирают ровно один раз
  (`decay`) — вместе со всем поддеревом, одним событием.
- **Ячейка** (`res`) — память в арене рамки. Умирает с рамкой.
- **Медиатор** (`med`) — проход к ячейке: {ячейка, владелец, поколение}.
  Единственный способ адресации — сырого адреса в языке нет, висячий
  указатель невыразим. Мёртвая рамка меняет поколение → все её медиаторы
  мертвы атомарно (ABA закрыт грамматикой).
- **Каскад** (`casc`/`acasc`) — единственный шаг вычисления, пересекающий
  границы рамок.
- **Decay** (`decay`) — единственный деструктор системы.

«Кто кого переживает» — сравнение глубин в дереве, O(1). Поэтому вся
проверка программы — один обход, а порождение легальных программ —
конечный автомат. Это сознательное урезание выразительности (дерево
вместо частичного порядка) ради проверяемости — главная заявка модели.

## Каскад — сердце языка

Каскад — блок, который трогает чужие ячейки. Два ортогональных режима:

**sync** — `casc NAME: M1,M2 -> OUT[CAV]` … `endc`

```
cav  session, field
res  draft, session, 16
med  draft_m, draft, session
casc edit: draft_m -> view[session]
    load  %r0, [draft_m + 0]   ; проверка поколения — ОДИН раз на входе
    add   %r1, %r0, %r0
    store [draft_m + 8], %r1   ; внутри — сырые смещения, ноль проверок
endc
```

- Все медиаторы обязаны быть живы на входе [I3] — проверяется статически.
- В runtime первый мёртвый медиатор = **атомарный abort**: блок
  пропускается целиком, программа продолжается. Не исключение, не UB —
  пропуск шага.
- Проверка поколения делается один раз на входе; внутри — сырые смещения.
  Это и есть стирание на горячем пути: цена пересечения границы видна в
  листинге поштучно.
- OUT — всегда новая ячейка; запись в существующую — через `store`.
- Из тела нельзя выпрыгнуть: выход только через `endc` или abort.

**async** — `acasc NAME: M1 -> OUT` … `endc`

Эффект, переживающий рамку (фон, отложенная задача). Правило: все
медиаторы и OUT — только в `field`. Если потребителя назвать не можете —
эффект не должен быть async; это не ограничение чекера, это диагноз
дизайна. OUT в field и есть «названный потребитель» — инвариант
механический, проверяется.

## Правила I1–I4 как таблица «что будет, если…»

| Правило | Смысл | Типичная ошибка | Диагностика |
|---|---|---|---|
| I1 | `res` — только в живой рамке | ячейка после `decay` рамки | `VIOLATION [I1]: cell in dead frame` |
| I2 | `med` выдаёт владелец или предок | соседняя рамка выдала проход | `[I2]: link issued by non-owner` |
| I3 sync | вход каскада — все медиаторы живы | каскад по проходу после decay | `[I3]: dead link on entry` |
| I3 async | связи и OUT — только field | фон держит ссылку на смертное | `[I3]: non-root link` |
| I4 | `raise` — только к строгому предку | подъём вбок/вниз | `[I4]: raise to non-ancestor` |
| DECAY | одна рамка — одна смерть | двойной `decay`, `decay field` | `[DECAY]: double leave` |

## Стирание (что платит машина)

| Инструкция | В C99 | Цена |
|---|---|---|
| `res` | bump-аллокация | 1 инструкция |
| `load`/`store` вне каскада | cmp gen + branch | 2 инструкции на обращение |
| `load`/`store` в каскаде | сырые смещения | 0 (проверка один раз на входе) |
| `casc` | блок + goto abort | проверки входа, далее 0 |
| `decay` | free арены + gen++ | 1 событие |
| `med` | {ptr, frame*, i32} | две проверки на границе (AUDIT-1/#4) |

Рантайма нет: дисциплина стирается, остаются проверки поколений на
границах. Полная таблица — SPEC.md §4.

## Инструментарий

```sh
rez3asm file.rza              # проверка: VIOLATION line N [RULE] в stderr
rez3asm file.rza --emit-c     # C99 на stdout (читаемый, для людей)
rez3asm file.rza --emit-lib   # C99-библиотека: procs → void rza_NAME(void)
bash run_tests.sh             # 12/12 тестов + ноль warnings zig cc -std=c99
```

- `rez3asm.c3` — транспайлер (C3 0.8.4; Python-версия перешита).
- `rez3ext.h` + `refs/rez3.h` — рантайм: арена, рамка с поколениями,
  `RezCellMed` (заморожен, расширяется только новыми файлами).
- `tests/` — легальные и `viol_*` программы; норма AUDIT-3: ожидаемые
  значения — с выводом, не магические константы.
- `lsp/` — LSP-сервер (Node, stdio) → диагностика I1–I4 в редакторе;
  `editors/vscode/` — расширение `rez3.rza` (подсветка + клиент).

## Пример целиком (tests/fib.rza)

```asm
cav  main, field
res  acc, main, 16
med  acc_m, acc, main

mov  %r0, 0
mov  %r1, 1
mov  %r2, 10

loop:
    brz  %r2, done
    add  %r3, %r0, %r1
    mov  %r0, %r1
    mov  %r1, %r3
    dec  %r2
    jmp  loop

done:
    store [acc_m + 0], %r0   ; 55: после 10 итераций (a,b)=(F(10),F(11))
    load  %r4, [acc_m + 0]
    print %r4
    decay main
    ret
```

## Границы (признаются, а не заметаются)

Циклические графы и совладение — вне модели (дерево строгое).
Вычислительные ядра — одна большая рамка + сырые указатели внутри.
async-транспорт — вне языка (acasc исполняется синхронно). Деление на
ноль — поведение C. Полный список — SPEC.md §8–§9.
