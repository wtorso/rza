# REZ3-ASM — спецификация ассемблерного слоя (.rza)

Типизированный ассемблер владения: плоский текст → статическая проверка
инвариантов I1–I4 → стирание в C99 поверх static runtime `refs/rez3ext.h`.
C89-эталон `refs/rez3.h` остаётся отдельной моделью, не зависимостью ASM.
Нормативная часть написана без метафор. Ссылки вида «AUDIT-1/#N» —
прослеживаемость норм к решениям архитектора.

---

## 0. Модель

Четыре кирпича, шесть имён, четыре инварианта. Отклонение = брак.

- **Field** — корневой пул памяти; единственная бессмертная рамка (имя
  `field`). Существует неявно; объявлять и разрушать его нельзя
  (AUDIT-1/#1: директивы `fld` в языке нет).
- **Cavity** — рамка-владелец: пара (Name, Body). Name = поколение
  (uint, монотонно до исчерпания, бессмертно, живёт вне арены). Body =
  bump-арена, смертна. Исчерпание даёт `FAULT` (§9).
- **Resonator** — ячейка: память в арене конкретной рамки; умирает с рамкой.
- **Mediator** — проход `{ячейка, текущий и домашний владельцы, поколения,
  размер}`; единственный легальный способ адресации ячейки (AUDIT-2/п.9).
  Мёртвый проход или доступ вне ячейки — fault, не UB.
- **Cascade** — блок-шаг; пересекает границы рамок только через медиаторы;
  первый мёртвый медиатор = атомарный abort блока.
- **Decay** — единственный деструктор системы: поколение++, арена
  освобождена одним событием, поддерево мертво рекурсивно.

Инварианты:

- I1: ячейка создаётся только в живой рамке.
- I2: медиатор выдаёт только владелец ячейки или его предок по дереву.
- I3: sync-каскад — все медиаторы живы на входе; async-каскад — медиаторы и
  out-ячейка только в field (out-ячейка и есть названный потребитель,
  AUDIT-1/#7).
- I4: raise — только к строгому предку.

Дисциплина имён: рамки, ячейки, медиаторы, метки — нижний регистр
(`[a-z_][a-z0-9_]*`); медиаторы — с суффиксом `_m`. ASM адаптирует
дисциплину имён IR к ассемблерному стилю (AUDIT-2/п.3).

## 1. Грамматика (EBNF)

```ebnf
program   = { stmt } ;
stmt      = own-stmt | data-stmt | flow-stmt
          | label | proc-open | casc-open | "endc" | "ret" ;

label     = name ":" ;
proc-open = "proc" name ":" ;                    (* тело до парного ret *)
casc-open = "casc"  name ":" med-list "->" name "[" name "]"
          | "acasc" name ":" med-list "->" name ; (* OUT всегда в field *)
med-list  = name { "," name } ;

own-stmt  = "cav"   name "," name                (* NAME, PARENT  *)
          | "res"   name "," name "," int        (* NAME, CAV, SIZE *)
          | "med"   name "," name "," name       (* NAME, RES, ISSUER *)
          | "raise" name "," name                (* RES, CAV *)
          | "decay" name                         (* CAV *)
          | "probe" name                         (* MED *)
          | ("load" | "loadb") reg "," mem ;   (* loadb — байт, AUDIT-4 *)

data-stmt = "mov" reg "," ( int | reg )
          | "store" mem "," reg
          | alu3 reg "," reg "," ( reg | int )   (* AUDIT-5: imm-форма *)
          | ("inc" | "dec") reg
          | "print" reg ;

flow-stmt = "jmp"  name
          | "brz"  reg "," name
          | "brnz" reg "," name
          | "call" name ;

mem       = "[" name "+" ( int | reg ) "]" ;   (* AUDIT-4: индексная адресация *)
alu3      = "add"|"sub"|"mul"|"div"|"mod"|"and"|"or"|"xor"|"shl"|"shr" ;
reg       = "%r" ("0".."15") ;
name      = "a".."z" | "_" , { "a".."z" | "0".."9" | "_" } ;
int       = [ "-" ] , digit , { digit }        (* десятичное *)
          | [ "-" ] , "0x" , hexdigit , { hexdigit } ;  (* AUDIT-5 *)
```

Комментарий: `;` до конца строки. Одна инструкция на строку. Метка — на
отдельной строке. `endc` — синтаксический терминатор блока каскада, не
операция модели (AUDIT-2/п.7); счёт операций модели остаётся восемь.
`cmp` в грамматике нет: ветвление по регистру, флагов нет (AUDIT-2/п.6).
ALU — только трёхоперандная форма (AUDIT-1/#1).

## 2. Семантика инструкций

Владение:

- `cav NAME, PARENT` — создать рамку NAME, ребёнка PARENT (`field` или
  живая рамка). Поколение новое, арена свежая.
- `res NAME, CAV, SIZE` — ячейка SIZE байт в арене живой рамки CAV [I1].
  Память нуле-инициализирована (AUDIT-6): чтение незаписанной ячейки даёт 0.
  Выделение и суммарная ёмкость рамки проверяются без переполнения.
- `med NAME, RES, ISSUER` — медиатор на ячейку; ISSUER — владелец ячейки
  или его предок (AUDIT-1/#5: выдающая рамка — явный операнд) [I2].
- `casc NAME: M1,M2 -> OUT[CAV]` … `endc` — sync-каскад: все медиаторы
  живы на входе [I3]; OUT — всегда НОВАЯ ячейка в рамке CAV
  (AUDIT-1/#6). Тело — только data-инструкции; load/store — только по
  медиаторам из списка входа; проверка поколения — один раз на входе
  (стирание). Первый мёртвый медиатор в runtime = атомарный abort:
  блок пропускается целиком, программа продолжается, exit-код не меняется.
- `acasc NAME: M1 -> OUT` … `endc` — async-каскад: все медиаторы указывают
  на ячейки field, OUT создаётся в field [I3-async]; проверка I3-async и
  есть реализация «названного потребителя» (AUDIT-1/#7). Транспорта нет:
  исполняется синхронно (см. §9).
- `raise RES, CAV` — CAV строгий предок текущего владельца RES [I4].
  Владелец меняется только для последующей статической проверки и новых
  медиаторов. Ранее выданные медиаторы сохраняют своего владельца. Любой
  доступ ограничен жизнью домашней арены независимо от текущего владельца.
- `decay CAV` — не `field`, не дважды [DECAY]; убивает рамку, поддерево,
  все ячейки и медиаторы на них. ASM: `decay`; IR: `leave`; C:
  `rez_decay`. `rez_leave` относится только к C89 heap-модели и не
  вызывается для generated static storage (AUDIT-2/п.1).
- `probe MED` — операция наблюдения (AUDIT-2/п.5): всегда печатает ровно
  одну строку `ALIVE` или `DEAD`. Поведение кода по результату probe —
  семантика намерения, не самого probe.
- `load %rN, [MED + off]` — чтение i64 через медиатор; мёртвый медиатор в
  runtime → `FAULT ...` в stderr и `exit(1)` (AUDIT-1/#3).
- `loadb %rN, [MED + off]` — чтение БАЙТА (zero-extend) через медиатор
  (AUDIT-4). Байтовые таблицы в ячейках — нормативный способ хранения данных.
- Смещение `off` у `load`/`loadb`/`store` — `imm | %rN`. Константный доступ
  вне ячейки — [STRUCT]; доступ по регистру проверяется в runtime и даёт
  `FAULT`. Отрицательное смещение и `off + width > SIZE` запрещены.

Данные и поток (i64-регистры `%r0`..`%r15`):

- `mov %rN, imm|%rM` — загрузка константы или копия регистра.
- `store [MED + off], %rN` — запись i64; только через медиатор.
  Записи байтов нет: байтовая таблица пишется i64-словами.
- `add sub mul inc dec` — wrapping i64 по mod 2^64; `and/or/xor` — побитовые.
- `div/mod` — `FAULT` при нулевом делителе и при `INT64_MIN / -1`.
- `shl` — сдвиг битового представления влево; `shr` — арифметический вправо.
  Отрицательный сдвиг или сдвиг >= 64 — `FAULT`.
- `name:` — метка текущего лексического блока.
- `jmp label` — безусловный переход; `brz %rN, label` — переход, если
  регистр == 0; `brnz` — если != 0.
- `proc NAME:` … `ret` — процедура; `call NAME` — вызов (см. §6).
- `print %rN` — печать i64 десятичной строкой.
- `ret` на верхнем уровне — конец программы, exit 0 (AUDIT-1/#1); легален
  только последней инструкцией верхнего уровня.

Ключевые правила:

- Сырого адреса как типа нет; инструкции «адрес ячейки в регистр» нет.
  Висячий указатель невыразим.
- Переходы — только на метки текущего лексического блока (верхний уровень,
  тело proc, тело каскада). Метки каскада не видны снаружи и наоборот.
  Выход из тела каскада — только через `endc` или abort; jmp из тела
  каскада наружу — violation (AUDIT-2/п.8). Нелокальный выход = цепочка
  decay.
- Вне каскада load/store проверяют жизнь и границы на каждом обращении;
  внутри каскада жизнь проверяется на входе, а границы — статически для
  константного смещения и в runtime для регистрового.
- Медиатор к собственной ячейке легален и обязателен: load/store идут
  только через медиатор (AUDIT-2/п.9).

## 3. Статические правила

Проверка — один текстовый проход; собираются ВСЕ нарушения; каждое — в stderr:
`VIOLATION line N [RULE]: msg`; exit 1, если есть хотя бы одно
(AUDIT-1/#10). Код при нарушениях не генерируется. Имена правил и
формулировки наследуют `rez3check.c`.

| Правило | Условие |
|---|---|
| I1 | `res`/`cav` в неизвестной или мёртвой рамке; out-ячейка каскада в мёртвой рамке |
| I2 | `med` на неизвестную ячейку; неизвестный issuer; issuer — не владелец и не предок владельца |
| I3 | sync-каскад: медиатор неизвестен или мёртв на входе; out-рамка неизвестна. async (I3-async): медиатор не на field-ячейку |
| I4 | `raise`: ячейка/цель неизвестны; цель — не строгий предок; цель мертва; ячейка в мёртвой рамке |
| DECAY | `decay` неизвестной рамки; двойной decay; decay `field`; decay рамки процедуры (её разрушает `ret`) |
| DUP | повторное имя рамки/ячейки/медиатора в скоупе; повторная метка в блоке; повторный proc |
| STRUCT | неизвестная инструкция/регистр/операнд; константный доступ вне ячейки; переполнение ёмкости рамки; `ret` не на месте; код после верхнеуровневого `ret`; переход на неизвестную или чужую метку; jmp из тела каскада наружу; load/store в каскаде по медиатору не из списка входа; владельческая операция в теле каскада; вложенный proc; незакрытый proc/casc; вызов неизвестной процедуры |
| SCOPE | из тела proc ссылка на глобальный медиатор, чья ячейка принадлежит proc-рамке (не field и не глобальная рамка — AUDIT-4), или на локальный медиатор другого proc (рамки и ячейки глобально видны — общая хроника, AUDIT-3; см. §6) |

**Осознанное решение (AUDIT-1/#3):** load/store/probe по статически
мёртвому медиатору — НЕ violation. Статический чекер проверяет только
I1–I4, DECAY, DUP, STRUCT, SCOPE. `load` по мёртвому медиатору легален
синтаксически и ловится в runtime: печать `FAULT line N: dead mediator M`
в stderr и `exit(1)`. IR-чекер `rez3check.c` в той же ситуации печатает
warn и продолжает — это разные роли инструментов (анализатор vs
транспайлер), а не разные семантики модели. Тест: `dead_link.rza`.

## 4. Таблица стирания (.rza → C99)

Медиатор хранит указатель, текущего и домашнего владельцев, два поколения и
размер. Нулевая цена безопасности не обещается: стираются только доказанные
проверки.

| Инструкция | Генерируемый C99 | Цена |
|---|---|---|
| `cav x, p` | `rez_cav_enter` над статическими рамкой и ареной; CAP = сумма align16(SIZE) + 16 на OUT, минимум 64 | reset без heap |
| `res x, f, S` | `rez_cell_z` + NULL → FAULT | checked bump + memset |
| `med x_m, c, i` | `rez_issue_cell(owner, home, cell, size)` | запись метаданных |
| `load`/`store` вне каскада | deref + bounds + FAULT | на каждом доступе |
| постоянный доступ в каскаде | `memcpy(..., width)` по входному указателю | проверки стерты |
| регистровый доступ в каскаде | `rez_cell_bounds` + FAULT + `memcpy` | одна проверка границ |
| вход в `casc` | `rez_deref_cell` на каждый вход; первый NULL → ABORT | один раз на входе |
| `raise` | ничего; домашняя рамка остаётся в медиаторе | 0 |
| `decay f` | guarded `rez_decay` рамки и каждого потомка | O(размер поддерева) |
| `probe m` | `ALIVE` только при живых владельцах и совпавших поколениях | deref + printf |
| `add/sub/mul/inc/dec` | wrapping helpers над `uint64_t` + `memcpy` | без signed UB |
| `div/mod/shl/shr` | guards + безопасный helper | FAULT на опасных операндах |
| метка / `jmp` | `L_x:` / `goto L_x;` | 0–1 |
| `brz` / `brnz` | `if (rN == 0) goto L_x;` / `!= 0` | 2 |
| `print` | `printf("%lld\n", (long long)rN);` | вызов printf |
| `proc`/`call`/`ret` | checked `rez_frame_reset`; `ret` = `rez_decay` | вызов + арена |
| `endc` | метка `casc_end_N:` + закрывающая скобка | 0 |

Оговорка по стандарту (AUDIT-1/#2): модель владения C89-совместима
(доказано `rez3.h` и `rez3check.c`); i64-датапath ассемблера (`int64_t`,
`stdint.h`, `%lld`) требует C99. Это компромисс датапath, не модели.
Сгенерированный код: `-std=c99 -pedantic -Wall -Wextra`, ноль
предупреждений (неиспользуемые входы рантайма глушатся взятием адреса).

слоях (AUDIT-1/#8).

## 6. Семантика proc (решение AUDIT-1; FIX не покрывал — открытый вопрос
закрыт локально; дополнено AUDIT-4)

AUDIT-4:
- Регистры приватны кадру proc: call создаёт новую рамку с чистыми
  r0..r15. Передача значений между proc — ТОЛЬКО через ячейки (записать
  поле, прочитать поле). Регистровый «результат» хелпера теряется при ret.
- Один `ret` на proc (ранний выход — через jmp на финальную метку).
- Медиаторы на ячейки, создаваемые внутри proc (лайфсайкл-проки
  lib-режима), объявляются на верхнем уровне; транспайлер инициализирует
  их сразу после кода создания ячейки в её proc (не в rza_boot — там
  ячейка ещё не существует).

- `proc NAME:` открывает процедуру до парного `ret`. Вложенные proc
  запрещены [STRUCT]. Незакрытый proc — [STRUCT].
- При каждом `call NAME` создаётся свежая рамка процедуры с именем NAME
  (родитель — `field`); при `ret` она разрушается (decay). В теле proc
  рамка процедуры адресуется по имени NAME: `cav local, NAME` и т.п.
  Явный `decay NAME` в теле запрещён [DECAY] — рамку разрушает `ret`.
- Имена, созданные внутри proc, — **рамки и ячейки глобальны** (общая
  хроника, AUDIT-3: lib-режиму нужен жизненный цикл, пересекающий вызовы);
  **медиаторы локальны** для процедуры-создателя (экспорт — геттером, §11).
  Повторное
  имя рамки/ячейки в любом proc или на верхнем уровне — [DUP].
- Из тела proc видны: локальные имена тела, `field`, глобальные рамки и
  ячейки (общая хроника, AUDIT-3) и глобальные медиаторы, чьи ячейки
  принадлежат `field` ИЛИ любой глобальной рамке (рамке, созданной на
  верхнем уровне или внутри proc — но не proc-рамке; AUDIT-4: такая рамка
  переживает любой вызов, а её смерть после определения proc ловится
  runtime-проверкой поколения). Медиаторы на ячейки proc-рамок и
  локальные медиаторы чужих proc из тела proc не видны — violation
  [SCOPE]: изоляция адресации сохраняется (медиатор — единственный путь
  к данным; рамки сами по себе данные не адресуют).
- Параметров у proc нет; обмен — через field-ячейки и их медиаторы
  (см. `tests/counter.rza`).
- Реализация: рамка процедуры — статическая `RezCavity` (имя бессмертно);
  на входе `rez_frame_reset` (та же структура, новое поколение —
  анти-ABA, свежая арена), на выходе `rez_decay`.

## 7. Prior art

- **TAL (Typed Assembly Language, Morrisett et al., 1996)** — типизированный
  ассемблер: инварианты проверяются на низком уровне и стираются при
  генерации. REZ3-ASM переносит идею с типов на владение.
- **WASM Component Model** — канонический ABI поверх линейного ядра:
  границы и владение явны, ресурсы имеют деструкторы. Здесь: границы =
  рамки, деструктор один (decay).
- **LLVM IR** — SSA-датапath и блочная структура переходов; наши
  лексические блоки меток — упрощённый аналог CFG.
- **Regions (Tofte–Talpin, 1994)** — регионы памяти с доказуемым временем
  жизни; рамка = регион с явным decay и поколениями против ABA.

## 8. Границы языка

Вне языка (осознанно): циклические графы владения (дерево рамок —
строгое), вычислительные ядра/векторизация, самомодифицирующийся код,
адресная арифметика вне медиаторов, async-транспорт (планировщик,
очереди, сеть), динамическая загрузка процедур.

## 9. Границы реализации

- **Арифметика**: `add/sub/mul/inc/dec` — wrapping i64; `div/mod` на нуле и
  `INT64_MIN / -1` — `FAULT`; сдвиг вне 0..63 — `FAULT`; `shr` арифметический.
- **acasc синхронен**: транспорта нет. События владения сериализованы;
  `rez_g_gen` не атомарен и не поддерживает гонки.
- **ABI lib-режима**: `RezCellMed` передаётся по значению и содержит size,
  owner/home и поколения. `REZ3EXT_ABI = 2`; все C TU пересобираются вместе.
- **OUT каскада** — всегда новая ячейка размером 8 байт.
- **raise — static-only**: память остаётся в домашней арене. Её decay делает
  доступ `FAULT`; релокации нет.
- **Мёртвый медиатор** при load/store/probe — runtime-fault, не violation
  (AUDIT-1/#3). Статическая смертность обязательна только на входе каскада [I3].
- **C99/C89**: модель C89-совместима; i64-датапath требует C99 (AUDIT-1/#2).
- **Границы ячейки**: константный выход — [STRUCT], регистровый — `FAULT`.
  Проверка учитывает ширину и запрещает целочисленный wrap.
- **Рекурсия proc запрещена**. Вызов вперёд запрещён, поэтому цикл вызовов
  прямой или косвенный невыразим.
- **proc закрывается `ret`**, последующий код принадлежит верхнему уровню.
  Верхний уровень пишется до proc или после всех proc явно.
- **Константы mov/ALU, SIZE и смещения ограничены i32** (AUDIT-4). Выход за
  диапазон — violation, не молчаливое усечение или ноль.
- **decay итеративен**: чекер и emitter используют `first_child/next_sibling`.
  Guards пропускают рамки, не созданные на текущем пути; повторный `rez_decay`
  безопасен.
- **ret разрушает рамку proc и в чекере** (AUDIT-7). Её поддерево мертво;
  доступ по медиатору ловится в runtime. Рамки под глобальными рамками не
  затрагиваются (AUDIT-3).
- **acasc и потребитель** (AUDIT-1/#6,#7): OUT создаётся при входе. До появления
  транспорта названным потребителем считается field; транспорт потребует новой
  нормы передачи OUT.
- **C-имена однозначны**: заглавные разделители отделяют scope. Имена языка
  строчные, поэтому склейки не пересекаются с верхнеуровневыми именами.
- **Имена host API зарезервированы всегда** (§11): proc ∉ {boot, arena_alloc,
  deref_cell} и не начинается с `frame_`/`med_`; рамка ≠ proc; имена медиаторов
  глобально уникальны. Ошибка обнаруживается чекером, не компилятором C.
- **Память статическая**: каждая рамка и её арена создаются при старте.
  После инициализации `malloc/realloc/free` не вызываются; decay только
  инвалидирует поколение и содержимое.
- **Бюджеты**: исходник CLI — 1048576 байт; до 16384 сущностей каждого вида;
  64 медиатора на ячейку и 64 входа каскада; 16777216 байт арены на рамку и
  67108864 байт на программу; generated C — 67108864 байт; workspace
  компилятора — 134217728 байт. Превышение даёт [STRUCT], не рост памяти.
- **Повторный `cav`**: вход в живую рамку — `FAULT`, а не потеря указателя.
  После decay структура используется повторно с новой ареной и поколением.
- **Исчерпание поколений**: нулевой счётчик запрещает новые enter/reset и даёт
  `FAULT` вместо повторного использования старого поколения.

## 10. Норма тестирования (AUDIT-3)

Каждое ожидаемое значение в тесте пишется с **выводом**, а не как магическая
константа: комментарий у `print`/`probe` обязан объяснять, почему ожидается
именно это (например: `; 55: после 10 итераций (a,b)=(F(10),F(11))=(55,89),
печатаем a`). Эталон, который нельзя перепроверить без исполнения, — бомба
замедленного действия в регрессионном наборе: «печатает число Фибоначчи»
легко принять за «печатает правильное число» (55 и 89 — соседние).

## 11. Lib-режим (--emit-lib, AUDIT-3)

`rez3asm file.rza --emit-lib` генерирует C99 без `main`. Процедуры и
глобальные сущности доступны хосту:

| .rza | C99 (lib-режим) |
|---|---|
| верхнеуровневый код | `void rza_boot(void)` — включая создание `field`; верхнеуровневый `ret` = конец `rza_boot`, не exit. **Однократно за процесс**: повторный вызов пересоздаёт field без decay (утечка + осиротевшие указатели хоста); рестарт = новый процесс |
| `proc NAME:` | `void rza_NAME(void)` — экспортируемая точка входа |
| рамка NAME | `RezCavity *rza_frame_NAME(void)` — геттер (для proc-рамок — `&f_P_NAME`) |
| медиатор NAME | `RezCellMed rza_med_NAME(void)` — геттер всех медиаторов |
| — | `void *rza_arena_alloc(RezCavity *c, size_t size)` — нуле-инициализированная bump-аллокация хоста |
| — | `void *rza_deref_cell(RezCellMed m)` — распечатка медиатора (NULL на мёртвом) |
| — | `unsigned rza_rez3ext_abi(void)` — значение `REZ3EXT_ABI` для проверки ABI хостом |

`print` использует printf. Остальная генерация совпадает с `--emit-c`.

Файл в lib-режиме — хроника одного полного жизненного цикла. Чекер
проверяет её один раз сверху вниз. Повторный вызов proc создаёт свежую
рамку через `rez_frame_reset`; `decay` гасит поддерево. Рамки и ячейки
глобальны. Из proc видны глобальные медиаторы на ячейки field и обычных
глобальных рамок, но не proc-рамок (§6). Хост получает медиаторы геттерами;
`rza_deref_cell` проверяет owner/home и оба поколения. Тесты:
`tests/lib_hello.rza` (+ `lib_harness.c`), `tests/lib_scope.rza`,
`tests/viol_scope.rza`.

## 12. LSP-режим (--lsp)

`rez3asm --lsp` — LSP 3.17 поверх stdio с Content-Length framing.
Поддержаны initialize, didOpen/didChange (Full sync)/didClose,
shutdown/exit. `didSave` не запускает проверку: она уже выполнена на
change. Пустой `contentChanges` и элементы без текста — no-op. Сообщение,
params, textDocument и элементы changes не-Object типа игнорируются.
Заголовок ограничен 8192 байтами, тело — 16777216 байтами. Открытых
документов — до 64, текст каждого — до 1048576 байт, URI — до 1024 байт.
До 65536 запятых JSON в одном сообщении; дерево проверяется до вызова parser.
Превышение любого предела завершает сервер с кодом 2. Неизвестный request
возвращает `-32601`; строковый `id` длиннее 256 байт — `-32600`.
Дробный числовой `id` возвращается без изменения; длинные `id` не обрезаются.
EOF — код 0; `exit` до shutdown — код 1.

Диагностика совпадает с CLI: `VIOLATION line N [RULE]`, code = RULE,
строка 1-based → 0-based. Один ответ ограничен 4194304 байтами и содержит
до 1000 исходных диагностик и одну сводную с числом скрытых. Текст одной
диагностики — до 256 UTF-8 байт без разрыва codepoint. Следующая валидация
сбрасывает сводку. Документы хранятся в fixed slots, JSON workspace
сбрасывается после сообщения. Реализация — `lsp_server.c3`, smoke и
RSS-проверка — `tests/lsp_smoke.py`.
