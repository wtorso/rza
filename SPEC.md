# REZ3-ASM — спецификация ассемблерного слоя (.rza)

Типизированный ассемблер владения: плоский текст → статическая проверка
инвариантов I1–I4 → стирание в C99 поверх рантайма `rez3.h` + `rez3ext.h`.
Нормативная часть написана без метафор. Ссылки вида «AUDIT-1/#N» —
прослеживаемость норм к решениям архитектора.

---

## 0. Модель

Четыре кирпича, шесть имён, четыре инварианта. Отклонение = брак.

- **Field** — корневой пул памяти; единственная бессмертная рамка (имя
  `field`). Существует неявно; объявлять и разрушать его нельзя
  (AUDIT-1/#1: директивы `fld` в языке нет).
- **Cavity** — рамка-владелец: пара (Name, Body). Name = поколение
  (uint, глобально монотонно, бессмертно, живёт вне арены). Body =
  bump-арена, смертна.
- **Resonator** — ячейка: память в арене конкретной рамки; умирает с рамкой.
- **Mediator** — проход `{ячейка, рамка-владелец, поколение}`; единственный
  легальный способ адресации ячейки — своей или чужой (AUDIT-2/п.9).
  Мёртвый проход — fault, не UB (AUDIT-1/#3).
- **Cascade** — блок-шаг; пересекает границы рамок только через медиаторы;
  первый мёртвый медиатор = атомарный abort блока.
- **Decay** — единственный деструктор системы: поколение++, арена
  освобождена одним событием, поддерево мертво рекурсивно.

Инварианты:

- I1: ячейка создаётся только в живой рамке.
- I2: медиатор выдаёт только владелец ячейки или его предок по дереву.
- I3: sync-каскад — все медиаторы живы на входе; async-каскад — медиаторы и
  out-ячейка только в field (out-ячейка и есть названный потребитель,
  AUDIT-1/#7).
- I4: raise — только к строгому предку.

Дисциплина имён: рамки, ячейки, медиаторы, метки — нижний регистр
(`[a-z_][a-z0-9_]*`); медиаторы — с суффиксом `_m`. ASM адаптирует
дисциплину имён IR к ассемблерному стилю (AUDIT-2/п.3).

## 1. Грамматика (EBNF)

```ebnf
program   = { stmt } ;
stmt      = own-stmt | data-stmt | flow-stmt
          | label | proc-open | casc-open | "endc" | "ret" ;

label     = name ":" ;
proc-open = "proc" name ":" ;                    (* тело до парного ret *)
casc-open = "casc"  name ":" med-list "->" name "[" name "]"
          | "acasc" name ":" med-list "->" name ; (* OUT всегда в field *)
med-list  = name { "," name } ;

own-stmt  = "cav"   name "," name                (* NAME, PARENT  *)
          | "res"   name "," name "," int        (* NAME, CAV, SIZE *)
          | "med"   name "," name "," name       (* NAME, RES, ISSUER *)
          | "raise" name "," name                (* RES, CAV *)
          | "decay" name                         (* CAV *)
          | "probe" name                         (* MED *)
          | ("load" | "loadb") reg "," mem ;   (* loadb — байт, AUDIT-4 *)

data-stmt = "mov" reg "," ( int | reg )
          | "store" mem "," reg
          | alu3 reg "," reg "," ( reg | int )   (* AUDIT-5: imm-форма *)
          | ("inc" | "dec") reg
          | "print" reg ;

flow-stmt = "jmp"  name
          | "brz"  reg "," name
          | "brnz" reg "," name
          | "call" name ;

mem       = "[" name "+" ( int | reg ) "]" ;   (* AUDIT-4: индексная адресация *)
alu3      = "add"|"sub"|"mul"|"div"|"mod"|"and"|"or"|"xor"|"shl"|"shr" ;
reg       = "%r" ("0".."15") ;
name      = "a".."z" | "_" , { "a".."z" | "0".."9" | "_" } ;
int       = [ "-" ] , digit , { digit }        (* десятичное *)
          | [ "-" ] , "0x" , hexdigit , { hexdigit } ;  (* AUDIT-5 *)
```

Комментарий: `;` до конца строки. Одна инструкция на строку. Метка — на
отдельной строке. `endc` — синтаксический терминатор блока каскада, не
операция модели (AUDIT-2/п.7); счёт операций модели остаётся восемь.
`cmp` в грамматике нет: ветвление по регистру, флагов нет (AUDIT-2/п.6).
ALU — только трёхоперандная форма (AUDIT-1/#1).

## 2. Семантика инструкций

Владение:

- `cav NAME, PARENT` — создать рамку NAME, ребёнка PARENT (`field` или
  живая рамка). Поколение новое, арена свежая.
- `res NAME, CAV, SIZE` — ячейка SIZE байт в арене живой рамки CAV [I1].
- `med NAME, RES, ISSUER` — медиатор на ячейку; ISSUER — владелец ячейки
  или его предок (AUDIT-1/#5: выдающая рамка — явный операнд) [I2].
- `casc NAME: M1,M2 -> OUT[CAV]` … `endc` — sync-каскад: все медиаторы
  живы на входе [I3]; OUT — всегда НОВАЯ ячейка в рамке CAV
  (AUDIT-1/#6). Тело — только data-инструкции; load/store — только по
  медиаторам из списка входа; проверка поколения — один раз на входе
  (стирание). Первый мёртвый медиатор в runtime = атомарный abort:
  блок пропускается целиком, программа продолжается, exit-код не меняется.
- `acasc NAME: M1 -> OUT` … `endc` — async-каскад: все медиаторы указывают
  на ячейки field, OUT создаётся в field [I3-async]; проверка I3-async и
  есть реализация «названного потребителя» (AUDIT-1/#7). Транспорта нет:
  исполняется синхронно (см. §9).
- `raise RES, CAV` — CAV строгий предок текущего владельца RES [I4];
  владелец ячейки меняется для последующей статической проверки; ранее
  выданные медиаторы на RES мертвы (несовпадение поколения). Имя
  канонично на всех слоях (AUDIT-1/#8, `lift` упразднён).
- `decay CAV` — не `field`, не дважды [DECAY]; убивает рамку, поддерево,
  все ячейки и медиаторы на них. ASM: `decay`; IR: `leave`; C:
  `rez_leave` (AUDIT-2/п.1).
- `probe MED` — операция наблюдения (AUDIT-2/п.5): всегда печатает ровно
  одну строку `ALIVE` или `DEAD`. Поведение кода по результату probe —
  семантика намерения, не самого probe.
- `load %rN, [MED + off]` — чтение i64 через медиатор; мёртвый медиатор в
  runtime → `FAULT ...` в stderr и `exit(1)` (AUDIT-1/#3).
- `loadb %rN, [MED + off]` — чтение БАЙТА (zero-extend) через медиатор
  (AUDIT-4). Байтовые таблицы в ячейках — нормативный способ хранения данных.
- Смещение `off` у `load`/`loadb`/`store` — `imm | %rN` (AUDIT-4: индексная
  адресация). Это не новая операция, а режим адресации существующих; без
  вычисляемого смещения невыразим класс программ с таблицами (сетки уровней,
  справочные таблицы физики).

Данные и поток (i64-регистры `%r0`..`%r15`):

- `mov %rN, imm|%rM` — загрузка константы или копия регистра.
- `store [MED + off], %rN` — запись i64; только через медиатор.
  Смещение `off` — `imm | %rN` (AUDIT-4). Записи байтов нет: байтовая
  таблица пишется i64-словами (таблица выровнена по 16 — см. арену).
- `add sub mul div mod and or xor shl shr %rD, %rA, %rB` — арифметика i64.
- `inc %rN` / `dec %rN` — ±1.
- `name:` — метка текущего лексического блока.
- `jmp label` — безусловный переход; `brz %rN, label` — переход, если
  регистр == 0; `brnz` — если != 0.
- `proc NAME:` … `ret` — процедура; `call NAME` — вызов (см. §6).
- `print %rN` — печать i64 десятичной строкой.
- `ret` на верхнем уровне — конец программы, exit 0 (AUDIT-1/#1); легален
  только последней инструкцией верхнего уровня.

Ключевые правила:

- Сырого адреса как типа нет; инструкции «адрес ячейки в регистр» нет.
  Висячий указатель невыразим.
- Переходы — только на метки текущего лексического блока (верхний уровень,
  тело proc, тело каскада). Метки каскада не видны снаружи и наоборот.
  Выход из тела каскада — только через `endc` или abort; jmp из тела
  каскада наружу — violation (AUDIT-2/п.8). Нелокальный выход = цепочка
  decay.
- Вне каскада load/store несут проверку медиатора на каждом обращении;
  внутри каскада — одну на входе (стирание на горячем пути).
- Медиатор к собственной ячейке легален и обязателен: load/store идут
  только через медиатор (AUDIT-2/п.9).

## 3. Статические правила

Проверка — один проход, O(n); собираются ВСЕ нарушения; каждое — в stderr:
`VIOLATION line N [RULE]: msg`; exit 1, если есть хотя бы одно
(AUDIT-1/#10). Код при нарушениях не генерируется. Имена правил и
формулировки наследуют `rez3check.c`.

| Правило | Условие |
|---|---|
| I1 | `res`/`cav` в неизвестной или мёртвой рамке; out-ячейка каскада в мёртвой рамке |
| I2 | `med` на неизвестную ячейку; неизвестный issuer; issuer — не владелец и не предок владельца |
| I3 | sync-каскад: медиатор неизвестен или мёртв на входе; out-рамка неизвестна. async (I3-async): медиатор не на field-ячейку |
| I4 | `raise`: ячейка/цель неизвестны; цель — не строгий предок; цель мертва; ячейка в мёртвой рамке |
| DECAY | `decay` неизвестной рамки; двойной decay; decay `field`; decay рамки процедуры (её разрушает `ret`) |
| DUP | повторное имя рамки/ячейки/медиатора в скоупе; повторная метка в блоке; повторный proc |
| STRUCT | неизвестная инструкция/регистр/операнд; `ret` не на месте; код после верхнеуровневого `ret`; переход на неизвестную или чужую метку; jmp из тела каскада наружу; load/store в каскаде по медиатору не из списка входа; владельческая операция в теле каскада; вложенный proc; незакрытый proc/casc; вызов неизвестной процедуры |
| SCOPE | из тела proc ссылка на глобальный медиатор, чья ячейка не принадлежит `field` (рамки и ячейки глобально видны — общая хроника, AUDIT-3; см. §6) |

**Осознанное решение (AUDIT-1/#3):** load/store/probe по статически
мёртвому медиатору — НЕ violation. Статический чекер проверяет только
I1–I4, DECAY, DUP, STRUCT, SCOPE. `load` по мёртвому медиатору легален
синтаксически и ловится в runtime: печать `FAULT line N: dead mediator M`
в stderr и `exit(1)`. IR-чекер `rez3check.c` в той же ситуации печатает
warn и продолжает — это разные роли инструментов (анализатор vs
транспайлер), а не разные семантики модели. Тест: `dead_link.rza`.

## 4. Таблица стирания (.rza → C99)

Медиатор — `{void *cell; RezCavity *owner; unsigned gen}` (16–24 байта,
AUDIT-1/#4): «две проверки на границе (указатель владельца + поколение),
стирается в sync-каскадах». Претензия на ноль накладных снята.

| Инструкция | Генерируемый C99 | Цена (машинных инструкций, типично) |
|---|---|---|
| `cav x, p` | `f_x = rez_enter(f_p, CAP);` — CAP статический: сумма SIZE всех res рамки с выравниванием 16 + 16 на каждую out-ячейку, минимум 64 | malloc ×2 + инициализация |
| `res x, f, S` | `c_x = rez_cell(f_f, S);` + проверка NULL → FAULT | bump: 2–3 + ветка |
| `med x_m, c, i` | `m_x_m = rez_issue_cell(f_owner, c_c);` | 3 store |
| `load` вне каскада | распечатка с проверкой: `rez_deref_cell` + `if (!p) FAULT/exit` | ~6–8 (две проверки) |
| `store` вне каскада | аналогично load | ~6–8 |
| `load`/`store` в каскаде | `*(int64_t*)((char*)p_m + off)` — сырой доступ по распечатанному на входе указателю | 1 |
| вход в `casc` | по одному `rez_deref_cell` на входной медиатор; первый NULL → `ABORT` в stderr + `goto casc_end_N` (abort ≠ fault: exit-код не меняется) | 2 проверки на медиатор, один раз |
| `raise` | ничего (статическая операция, см. §9) | 0 |
| `decay f` | `rez_decay(f_f)` = `rez_leave` (AUDIT-2/п.1: `#define rez_decay rez_leave`) | gen++ + free |
| `probe m` | `printf("%s\n", rez_deref_cell(m) ? "ALIVE" : "DEAD");` | вызов printf |
| `mov/ALU/inc/dec` | оператор C над локальными `int64_t r0..r15` | 1–2 |
| метка / `jmp` | `L_x:` / `goto L_x;` (метки блоков с префиксом) | 0–1 |
| `brz` / `brnz` | `if (rN == 0) goto L_x;` / `!= 0` | 2 |
| `print` | `printf("%lld\n", (long long)rN);` | вызов printf |
| `proc`/`call`/`ret` | `static void p_x(void)`; `call` = `p_x()` = enter рамки процедуры (`rez_frame_reset`), `ret` = её `rez_decay` | вызов функции |
| `endc` | метка `casc_end_N:` + закрывающая скобка блока | 0 |

Оговорка по стандарту (AUDIT-1/#2): модель владения C89-совместима
(доказано `rez3.h` и `rez3check.c`); i64-датапath ассемблера (`int64_t`,
`stdint.h`, `%lld`) требует C99. Это компромисс датапath, не модели.
Сгенерированный код: `-std=c99 -pedantic -Wall -Wextra`, ноль
предупреждений (неиспользуемые входы рантайма глушатся взятием адреса).

## 5. Таблица отображения слоёв (нормативная)

| Модель | IR (.rz3) | ASM (.rza) | C |
|---|---|---|---|
| enter | `frame` | `cav` | `rez_enter` |
| leave | `leave` | `decay` | `rez_leave` (= `rez_decay`) |
| resonator | `cell` | `res` | `rez_cell` |
| mediator | `link` | `med` | `RezCellMed` / `rez_issue_cell` |
| read | `read` | `load` | `rez_deref_cell` |
| cascade | `casc` / `acasc` | `casc`…`endc` / `acasc`…`endc` | блок + `goto` abort |
| raise | `raise` | `raise` | — (static-only) |
| alive? | `probe` | `probe` | `printf` |

Имена: IR — КАПС, ASM — нижний регистр с суффиксом `_m` у медиаторов
(AUDIT-2/п.3). `read` как владельческая операция остаётся только в IR;
в ASM данные читает `load` (AUDIT-2/п.4). `raise` — одно имя на всех
слоях (AUDIT-1/#8).

## 6. Семантика proc (решение AUDIT-1; FIX не покрывал — открытый вопрос
закрыт локально; дополнено AUDIT-4)

AUDIT-4 (по опыту ядра физики bond):
- Регистры приватны кадру proc: call создаёт новую рамку с чистыми
  r0..r15. Передача значений между proc — ТОЛЬКО через ячейки (записать
  поле, прочитать поле). Регистровый «результат» хелпера теряется при ret.
- Один `ret` на proc (ранний выход — через jmp на финальную метку).
- Медиаторы на ячейки, создаваемые внутри proc (лайфсайкл-проки
  lib-режима), объявляются на верхнем уровне; транспайлер инициализирует
  их сразу после кода создания ячейки в её proc (не в rza_boot — там
  ячейка ещё не существует).

- `proc NAME:` открывает процедуру до парного `ret`. Вложенные proc
  запрещены [STRUCT]. Незакрытый proc — [STRUCT].
- При каждом `call NAME` создаётся свежая рамка процедуры с именем NAME
  (родитель — `field`); при `ret` она разрушается (decay). В теле proc
  рамка процедуры адресуется по имени NAME: `cav local, NAME` и т.п.
  Явный `decay NAME` в теле запрещён [DECAY] — рамку разрушает `ret`.
- Имена, созданные внутри proc, — **рамки и ячейки глобальны** (общая
  хроника, AUDIT-3: lib-режиму нужен лайфсайкл рамок, пересекающий
  процедуры — `game/arch/game.rza`); **медиаторы локальны** для
  процедуры-создателя (экспорт наружу — геттером, см. §11). Повторное
  имя рамки/ячейки в любом proc или на верхнем уровне — [DUP].
- Из тела proc видны: локальные имена тела, `field`, глобальные рамки и
  ячейки (общая хроника, AUDIT-3) и глобальные медиаторы, чьи ячейки
  принадлежат `field` (бессмертны). Ссылка из proc на глобальный
  медиатор, чья ячейка не в `field`, — violation [SCOPE]: изоляция
  адресации сохраняется (медиатор — единственный путь к данным; рамки
  сами по себе данные не адресуют).
- Параметров у proc нет; обмен — через field-ячейки и их медиаторы
  (см. `tests/counter.rza`).
- Реализация: рамка процедуры — статическая `RezCavity` (имя бессмертно);
  на входе `rez_frame_reset` (та же структура, новое поколение —
  анти-ABA, свежая арена), на выходе `rez_decay`.

## 7. Prior art

- **TAL (Typed Assembly Language, Morrisett et al., 1996)** — типизированный
  ассемблер: инварианты проверяются на низком уровне и стираются при
  генерации. REZ3-ASM переносит идею с типов на владение.
- **WASM Component Model** — канонический ABI поверх линейного ядра:
  границы и владение явны, ресурсы имеют деструкторы. Здесь: границы =
  рамки, деструктор один (decay).
- **LLVM IR** — SSA-датапath и блочная структура переходов; наши
  лексические блоки меток — упрощённый аналог CFG.
- **Regions (Tofte–Talpin, 1994)** — регионы памяти с доказуемым временем
  жизни; рамка = регион с явным decay и поколениями против ABA.

## 8. Границы языка

Вне языка (осознанно): циклические графы владения (дерево рамок —
строгое), вычислительные ядра/векторизация, самомодифицирующийся код,
адресная арифметика вне медиаторов, async-транспорт (планировщик,
очереди, сеть), динамическая загрузка процедур.

## 9. Открытые вопросы

- **Деление на ноль** (`div`, `mod`): поведение C (UB на нуле). Норму
  (fault vs abort) надо принимать отдельно; сейчас не специфицировано.
- **acasc исполняется синхронно**: транспорта нет, генерация идентична
  sync-каскаду; production-долг — транспорт вне модели (честная оговорка).
- **OUT каскада фиксирован 8 байтами** (один i64): синтаксис `OUT[CAV]`
  размера не несёт. Расширение — отдельным решением.
- **raise — static-only**: физическая память ячейки остаётся в арене
  рамки рождения (bump-арены не перемещают); легальная программа обязана
  не обращаться к поднятой ячейке после decay рамки рождения — иначе
  use-after-free, который модель не ловит (тест `cascade.rza`
  демонстрирует легальный паттерн). Релокация при raise — production-долг.
- **load/store по статически мёртвому медиатору** — runtime-fault, а не
  violation (AUDIT-1/#3, см. §3). Осознанный выбор: статическая проверка
  смертности ограничена входами каскадов [I3].
- **C99 vs C89**: оговорка AUDIT-1/#2 (см. §4): модель C89-совместима,
  датапath — нет.
- **Пространственной безопасности нет** (review P4): медиатор не несёт
  размера ячейки, смещения не проверяются — `store [m + 8000]` пишет за
  границу буфера арены. Модель закрывает ВРЕМЕННУЮ безопасность (поколения),
  не пространственную. Реализация bounds — отдельное решение (размер в
  RezCellMed + проверка на границе, в каскаде стираемо на входе).
- **Рекурсия proc**: прямой самовызов запрещён статически (STRUCT);
  косвенные циклы вызовов не отслеживаются — frame_reset освобождает арену
  живого кадра (use-after-free по построению). Правило проекта: циклов
  вызовов нет.
- **proc закрывается `ret`**; последующий код — верхний уровень (намеренно:
  `counter.rza` вызывает proc после определения). Отличить «случайно
  после ret» от «намеренно наверху» синтаксически нельзя (review P3) —
  правило проекта: исполняемый верхний уровень пишется до proc или после
  всех proc явно.
- **mov imm ограничен i32** (AUDIT-4): константы до 32 бит; большее —
  violation (раньше молча обрезалось — исправлено, прецедент нормы
  «нет молчаливой неправильности»).

## 10. Норма тестирования (AUDIT-3)

Каждое ожидаемое значение в тесте пишется с **выводом**, а не как магическая
константа: комментарий у `print`/`probe` обязан объяснять, почему ожидается
именно это (например: `; 55: после 10 итераций (a,b)=(F(10),F(11))=(55,89),
печатаем a`). Эталон, который нельзя перепроверить без исполнения, — бомба
замедленного действия в регрессионном наборе: «печатает число Фибоначчи»
легко принять за «печатает правильное число» (55 и 89 — соседние).
Прецеденты: двухоперандная грамматика против трёхоперандного эталона,
`store %r1` (89) вместо `store %r0` (55) в fib — обе ошибки пойманы прогоном,
а не ревью.

## 11. Lib-режим (--emit-lib, AUDIT-3)

`rez3asm file.rza --emit-lib` генерирует C99 БЕЗ `main` — библиотеку
жизненного цикла для встраивания в хост (у нас — игра на C3, линковка
объектником). Проверки, диагностика и однопроходность — без изменений.

Отображение имён:

| .rza | C99 (lib-режим) |
|---|---|
| верхнеуровневый код | `void rza_boot(void)` — включая создание `field`; верхнеуровневый `ret` = конец `rza_boot`, не exit |
| `proc NAME:` | `void rza_NAME(void)` — экспортируемая (не static) точка входа хоста |
| рамка NAME | `RezCavity *rza_frame_NAME(void)` — геттер (для proc-рамок — `&f_proc_NAME`) |
| медиатор NAME | `RezCellMed rza_med_NAME(void)` — геттер (всех медиаторов, включая созданные в proc) |
| — | `void *rza_arena_alloc(RezCavity *c, size_t size)` — bump-аллокация хоста в арене рамки (обёртка над static `rez_arena_alloc` из rez3.h) |
| — | `void *rza_deref_cell(RezCellMed m)` — распечатка медиатора (NULL на мёртвом) |

`print` в lib-режиме — по-прежнему printf (отладка). Остальная генерация
идентична `--emit-c`.

Семантика хроники (AUDIT-3): .rza-файл в lib-режиме читается как
нормативная хроника одного полного прохода жизненного цикла; чекер
проверяет его один раз сверху вниз. Повторные вызовы точек входа хостом
(новая партия, новая волна) корректны по построению: рамка процедуры
переинициализируется `rez_frame_reset` (новое поколение, анти-ABA),
`cav` создаёт свежую рамку, `decay` гасит поддерево. Ослабление SCOPE
(§6) касается только рамок и ячеек — они не адресуют данные; медиаторы
(единственный путь к данным) по-прежнему видны из proc только на
field-ячейки, а экспорт медиаторов хосту идёт геттерами и подчиняется
проверке поколения в `rza_deref_cell`. Тесты: `tests/lib_hello.rza`
(+ `lib_harness.c`), `tests/lib_scope.rza`, `tests/viol_scope.rza`.
