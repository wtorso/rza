# RZA 0.3.0 prerelease

RZA 0.3.0 adds typed procedure contracts for explicit mediator access. It remains a
prerelease: the language and host interfaces can still change.

## Typed procedure contracts

```asm
proc convert(input_m: ro, result_m: rw):
```

- `ro` permits loads, probes, view construction, and use as a cascade input. `rw`
  also permits stores. An empty `proc pure():` contract permits no mediator access.
- Local views inherit their source capability. Global views require their own
  contract entry; listing the source does not authorize an alias.
- A contracted caller must satisfy its callee's contract at every call edge and
  cannot escalate `ro` to `rw`. Contracted procedures cannot call legacy procedures.
- Access through an unlisted mediator is a static `VIOLATION`. Diagnostics name the
  procedure, and call failures name the direct callee.
- Contracts hold at most 64 existing global mediators. Malformed, duplicate, and
  unknown entries are rejected. Legacy `proc name:` behavior is unchanged.

Contracts erase completely before C generation. They add no runtime layout,
instruction, or host ABI change. `REZ3EXT_ABI` remains 5; hosts built for 0.2.0 must
still use matching generated code and headers as before.

## Verification and measured cost

- Directed tests cover direct access, local/global views, probes, sync/async
  cascades, legacy interoperability, and transitive capability escalation.
- A separate capability model drives 64 valid and 64 invalid deterministic programs.
  Every generated operation occurs in both outcomes; invalid programs must produce
  the modeled diagnostic count and no C output. A shrinker and deliberate harness
  mismatches guard the oracle itself.
- Calls, ring buffer, parser/state-machine, and binary protocol workloads now use
  minimal contracts. Existing outputs and quota, truncation, and length-attack cases
  are unchanged.
- On the release development machine with GCC, normalized generated C and compared
  RZA binaries were byte-identical to their legacy equivalents. In a 1024-procedure
  synthetic workload, 20 transpile samples had medians of 70.68 ms without contracts
  and 71.65 ms with contracts. These are local measurements, not universal claims.
- The full suite expects `PASS=207 FAIL=0` on POSIX and Windows MSVC, and 206 on
  Windows Zig because its Rust static-library link has a compiler-rt conflict. CI
  covers GCC, Clang, Zig, Windows, ASan/UBSan, reproducible packages, and editors.

## Archives and requirements

- `rza-0.3.0-linux-x86_64.tar.gz`: Linux x86_64, built on Ubuntu 24.04.
- `rza-0.3.0-windows-x86_64.tar.gz`: Windows x86_64 with `rez3asm.exe`, using the
  dynamic Microsoft C runtime (`VCRUNTIME140.dll` and `dbghelp.dll`).
- C3 is not needed to run the packaged compiler. A C23 compiler is required for
  generated C; C3 0.8.5_1 is needed only to rebuild the compiler from source.
- Other targets, a native optimizing backend, OS-thread parallelism, and
  cryptographic signatures are not included.

Download the archive for your platform and `SHA256SUMS`, then run:

```sh
sha256sum --check --ignore-missing SHA256SUMS
tar -xzf rza-0.3.0-linux-x86_64.tar.gz
cd rza-0.3.0-linux-x86_64
./rez3asm --version
./rez3asm examples/hello.rza --emit-c -o hello.c
cc -std=c23 -O2 -Wall -Wextra -Werror -I include/rza hello.c -o hello
./hello
```

Expected program output is `41`. `RELEASE.txt` records the version, full source
commit, target, C3 version, and `RZA_DIRTY=0`. Packages are built in two clean
checkouts and must be byte-identical. Checksums verify integrity, not authorship.
