# RZA 0.2.0 prerelease

RZA 0.2.0 adds zero-copy bounded views and controlled host-visible execution.
It remains a prerelease: the language and host interfaces can still change.

## Highlights

- `view DST, SOURCE, OFFSET, LENGTH` creates a bounded mediator without
  allocating or copying data. Raw ranges use bytes; typed ranges use elements.
  Nested and empty views retain lifetime and generation checks. Host-created
  mediators must contain valid aligned metadata and describe the actual object
  extent; arbitrary non-null C addresses are not validated.
- Generated libraries no longer terminate the host process or print by default.
  Exported boot and procedure calls return `RzaResult`; `rza_await` returns an
  `RzaAwaitResult`. Standalone diagnostics and exit statuses are unchanged.
- Runtime faults cancel queued async work and clear pending flags. Async OUT
  cells reuse their fixed eight bytes with a new allocation generation, keeping
  stale mediators and views invalid across repeated publication.
- The protocol benchmark uses bounded payload views instead of a scratch copy.
  Full words are loaded directly and short words are assembled with zero padding.
- The language server, VS Code extension, Emacs mode, and Neovim syntax support
  the new `view` opcode. Differential execution covers 183 programs plus
  adversarial mutation and shrinking checks.

## Breaking host changes

`REZ3EXT_ABI` is 5. Rebuild generated code and every host translation unit with
the same headers.

- `rza_boot` and exported procedures now return `RzaResult`, not `void`.
- `rza_await` returns `RzaAwaitResult`, not `uint64_t`.
- `RezAsyncRun` returns `RzaResult`; `rez_async_drain` returns `RzaAwaitResult`.
- `RezCellMed` is 56 bytes on x86-64 and includes optional allocation-generation
  metadata used by async OUT mediators and views.
- Boot is single-shot. Repeated boots and reentrant execution return
  `RZA_FAULT_ENTRY_STATE`. Procedures can be called again after success or fault.
- Faults do not roll back earlier writes. Hosts must repair or discard affected
  application state as appropriate.

A generated library does not call `exit` or print diagnostics by default. Use
`rza_set_diagnostic_handler` to receive structured diagnostics. Standalone
programs preserve the previous diagnostic text and exit status.

## Platforms and requirements

- `rza-0.2.0-linux-x86_64.tar.gz`: Linux x86_64, built on Ubuntu 24.04.
- `rza-0.2.0-windows-x86_64.tar.gz`: Windows x86_64 with `rez3asm.exe`, using
  dynamic Microsoft C runtime components (`VCRUNTIME140.dll` and `dbghelp.dll`).
  A static CRT is not included.
- C3 is not needed to run the packaged compiler.
- A C23 compiler is required to compile generated C. C3 0.8.5_1 is needed only
  when rebuilding the RZA compiler from source.
- Other operating systems, architectures, static linking, a native optimizing
  backend, OS-thread parallelism, and cryptographic signatures are not included.

## Verify and run

Download the archive for your platform and `SHA256SUMS`, then run the following.
`--ignore-missing` skips the other platform's archive in the checksum file:

```sh
sha256sum --check --ignore-missing SHA256SUMS
tar -xzf rza-0.2.0-linux-x86_64.tar.gz
cd rza-0.2.0-linux-x86_64
./rez3asm --version
./rez3asm examples/hello.rza --emit-c -o hello.c
cc -std=c23 -O2 -Wall -Wextra -Werror -I include/rza hello.c -o hello
./hello
```

Expected program output is `41`. Use the corresponding Windows archive and
`rez3asm.exe` on Windows.

`RELEASE.txt` records the version, full source commit, target, C3 version, and
`RZA_DIRTY=0`. Packages are built in two clean checkouts and must be byte-identical.
Checksums verify integrity, not a cryptographic signature.

From the extracted package, install for the current user with:

```sh
RZA_COMPILER=./rez3asm PREFIX="$HOME/.local" bash install.sh
export PATH="$HOME/.local/bin:$PATH"
```

The full suite expects `PASS=205 FAIL=0` on POSIX and Windows MSVC, and 204 on
Windows Zig because its Rust static-library link has a compiler-rt conflict. CI
covers GCC, Clang, Zig, Windows, ASan/UBSan, reproducible packages, editor tests,
and release dry runs.
