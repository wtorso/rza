# RZA 0.4.0 prerelease

RZA 0.4.0 adds the complete fixed-width integer core and strict floating-point operations for
binary32 and binary64. It remains a prerelease: the language and host interfaces can still
change. The host ABI remains `REZ3EXT_ABI = 5`.

## Fixed-width integers

- Signed and unsigned `i8/u8`, `i16/u16`, `i32/u32`, `i64`, and `u64` operations use explicit
  types, widths, literals, wrapping arithmetic, checked arithmetic, division, shifts, and
  comparisons. The integer core has 172 operation/type spellings.
- Exact-width loads and stores preserve adjacent bytes. Conversion and callback checks define
  faults and prevent result publication after a violation.
- Typed layouts, views, procedure contracts, and synchronous/asynchronous cascades use the same
  ownership and memory rules across the numeric types.

## Strict floating point

- `f32` and `f64` support literals, moves, exact-width memory access, arithmetic, comparisons,
  conversions, and bit casts. Together these add 68 spellings for a closed matrix of 240 integer
  and floating-point forms.
- Arithmetic uses result-width rounding with round-to-nearest, ties-to-even in supported strict
  build configurations. Signed zeros, infinities, subnormals, and NaNs are defined. Division by
  zero is non-trapping.
- Ordered comparisons are false for NaN, while `fne` is true. After arithmetic or numeric
  conversion, tests require only the is-NaN predicate, not a particular NaN payload. Bit-copy
  operations preserve exact bits.
- The conversion matrix covers integer/floating pairs, `f32`/`f64` conversion, and same-width
  integer/floating bit casts. Out-of-range and non-finite numeric conversions produce
  `invalid conversion` before stores, callbacks, or asynchronous OUT publication.
- An `f32` value occupies the low 32 bits of its container with zero upper bits. An `f64` value
  uses the full container. Loads and stores copy exactly four or eight bytes.
- Generated C uses strict floating-point flags and compiler-generated assembly probes. Fast-math
  and unintended fused contraction are rejected by the test suite rather than accepted as
  alternative results.

## Editors and platform support

- VS Code and Neovim provide syntax and language-client integration through the same `rez3asm`
  compiler and `rez3asm --lsp` server. Emacs and Vim provide lightweight editing support.
- CI covers GCC, Clang, Zig, MSVC, Windows, host ASan/UBSan, and AArch64/RV64 through QEMU.
  Reproducible archives, independent-checkout comparison, and install smoke are release gates.
- The expected suite results are 332 passing tests on POSIX and MSVC, and 331 on Windows Zig,
  where the native Rust static-library comparison is not linked. Each QEMU target expects 212
  passing tests and 1540 logged executions.
- Six differential oracles and 93 direct workloads cover the numeric and ownership models.
  Generated-C compatibility checks retain 120 accepted sources and 78 rejected cases; an empty
  corpus is not accepted as evidence.

## Archives and requirements

- `rza-0.4.0-linux-x86_64.tar.gz`: Linux x86_64, built on Ubuntu 24.04.
- `rza-0.4.0-windows-x86_64.tar.gz`: Windows x86_64 with `rez3asm.exe`, using the dynamic
  Microsoft C runtime (`VCRUNTIME140.dll` and `dbghelp.dll`).
- C3 is not needed to run the packaged compiler. A C23 compiler is required for generated C;
  C3 0.8.5_1 is needed only to rebuild the compiler from source.
- Real-hardware, big-endian, other libc/ABI, and cross-target sanitizer coverage is not claimed.
  `f16`/`bf16`, AI/GPU profiles, a native optimizing backend, OS-thread parallelism, and
  cryptographic signatures are not included.

Download the archive for your platform and `SHA256SUMS`, then run:

```sh
sha256sum --check --ignore-missing SHA256SUMS
tar -xzf rza-0.4.0-linux-x86_64.tar.gz
cd rza-0.4.0-linux-x86_64
./rez3asm --version
./rez3asm examples/hello.rza --emit-c -o hello.c
cc -std=c23 -O2 -Wall -Wextra -Werror -fno-fast-math -ffp-contract=off \
  -fexcess-precision=standard -I include/rza hello.c -o hello
./hello
```

Expected version output is `rez3asm 0.4.0`, and the example prints `41`. `RELEASE.txt` records
the version, full source commit, target, C3 version, and `RZA_DIRTY=0`. Packages are built in two
clean checkouts and must be byte-identical. Checksums verify integrity, not authorship.
